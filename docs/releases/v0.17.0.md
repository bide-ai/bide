**Approvers decide with their own keys, wherever those keys live, and you can prove every notice went out.**

v0.17.0 adds separation of duties to approval gates, an approval intake and a browser approve page, the `bide approve` command, signing keys in an HSM or a cloud key service, and a notifier that routes, escalates, sends an all-clear and can sign its trail, with an offline audit that checks every notice was delivered and acknowledged.

- **Separation of duties.** `ApprovalPolicy.ExcludePrincipal` (in a flow config, `approval: {..., exclude_principal: true}`) makes an m-of-n gate never count a decision by whoever requested the run, or any run above it. A run records its principal (`run:principal`) before it starts, the audit recounts with the same exclusion, `bide view` and `bide approve` honour it, and model 1b checks it up a delegation chain. A gate whose policy gains the exclusion after a tally passed asks again. `examples/approval/makerchecker` runs a maker-checker refund.

- **Approvers sign with their own keys.** `bide keygen` creates an approver key (Ed25519, ECDSA P-256, ML-DSA-65 or the hybrid) and `bide approve` shows a waiting call from the journal, the SHA-256 of the arguments it signs, and records the signed decision with a receipt (`audit.DecisionReceipt`, checked with `bide audit verify-receipts`). `bide approve -list` lists what waits. `bide approve -to <url>` decides through an application's approval intake instead of writing the journal.

- **An approval intake and a browser approve page.** Package `approvals` is an `http.Handler` an application mounts: it shows a gated call from the journal, verifies a signed decision against the recorded call and the approver's enrolled key, records it through the application's own journal (so an `audit.AuditedStore` signs it as it is written) and returns a receipt. It evaluates the gate with `agent.EvaluateGate`, the function the agent's own gate uses. A static approve page signs a decision in the browser with a non-extractable key. Each release now publishes the page bundle's SHA-256 sums, signed, for an organization that hosts the page on an origin of its own ([verify the bundle](https://github.com/bide-ai/bide/blob/v0.17.0/docs/trust/verify-releases.md#verify-the-approve-page-bundle)). See the [human approval guide](https://github.com/bide-ai/bide/blob/v0.17.0/docs/guides/hitl-approval.md).

- **Signing keys in an HSM or a cloud key service.** New modules `signer/pkcs11`, `signer/awskms`, `signer/gcpkms` and `signer/azurekv` sign tree heads, evidence, grants and approver decisions without the private key entering the application, with ECDSA P-256 beside Ed25519 for key services that cannot sign Ed25519. Each signs once at open, checks every signature against the key's public key, and refuses a key that is software-backed or extractable unless told otherwise; the Cloud KMS signer can verify the key's Cloud HSM attestation. `bide-hsm approve` is `bide approve` for an approver key in an HSM, a smart card, AWS KMS, Google Cloud KMS or Azure Key Vault (installed from source; it needs cgo). See the [key custody guide](https://github.com/bide-ai/bide/blob/v0.17.0/docs/guides/key-custody.md).

- **A notifier that routes, escalates and sends an all-clear.** `WithNotifyReceiver`, `WithNotifyRoute` and `WithNotifyApproverRoute` send approvals to the approvers' channel and halts to on-call, each receiver with its own audited delivery and acknowledgement. `WithNotifyEscalation` tells the next receiver when an event is not handled by its deadline. When an event stops being current, a `resolved` notification lets a receiver close the incident it opened. The notification trail can be signed and anchored as it is written (`audit.NewAuditedEventStore`), and `bide notify test`, `listen` and `relay` check a receiver end to end and forward bide's webhooks to Slack and PagerDuty. TLA+ model 14 covers the all-clear, routing and escalation. See the [notifications guide](https://github.com/bide-ai/bide/blob/v0.17.0/docs/guides/notifications.md).

- **Proof that notices went out.** `bide audit notifications` checks offline that every event that needed a person was notified and acknowledged, and when, cross-checked against the run journals and, with signed heads, against tampering. `bide view` gains a Needs attention list of every run waiting on a person.

- **Operations.** `bide migrate` and `postgres.WithoutMigration` split schema ownership from the application's database role, and every open of a Postgres store checks the schema it finds. `RecoverLoop` re-signs a run that ended waiting on a person, and `bide audit verify-decision-coverage` flags a decision no signed head covers. The evidence format `bide.audit.evidence.v6` seals a hash, so a KMS with a size limit can seal a package of any size. SQLite writers in one process take turns instead of failing with `SQLITE_BUSY`. `bide demo` now opens with the double charge a naive retry makes, and `docs/trust/` has a threat model, a stability policy and release verification.

API changes:

- Added: package `approvals` (`New`, `WithGatePolicy`, `WithAuth`, `WithCORS`, `WithCORSCredentials`, `WithPage`, `PageFiles`, `PageSHA256`, `PageCSP`); modules `signer/pkcs11`, `signer/awskms`, `signer/gcpkms`, `signer/azurekv`, `notify/relay` and the command module `cmd/bide/bide-hsm`; `agent.EvaluateGate`, `GateReask`, `RunPrincipal`, `PendingSoDReapproval`, `HeldDecisionStep`, `IsDecisionStepName`, `ReportWritten`, `RootRunID`, `WithNotifyReceiver`, `WithNotifyRoute`, `WithNotifyApproverRoute`, `WithNotifyEscalation`, `RoutingOf`, `WithReanchor`; `audit.ECDSAP256Signer`, `DecisionReceipt`, `CheckReceipt`, `NewAuditedEventStore`, `VerifyNotifications`, `CheckDecisionCoverage`, `ErrRootMismatch`; `postgres.WithoutMigration`, `Migrate`; the CHANGELOG lists the rest.
- New commands: `bide approve`, `bide keygen`, `bide notify` (`test`, `listen`, `relay`), `bide migrate`, `bide audit notifications`, `bide audit verify-receipts`, `bide audit verify-decision-coverage`, and `bide-hsm`.
- Changed: `plan.Flow.Run` takes run options, of which only `agent.WithIdentity` is accepted.

Behaviour changes:

- **The approval intake needs `WithGatePolicy`.** `approvals.New` refuses to build a handler without it (and without `WithAuth`): the handler counts a gate under the live policy the agent is built with, so a policy changed after the first pause, such as `ExcludePrincipal` turned on, is honoured.
- **A nonzero `-max-unattested` trusts unsigned records.** `bide audit notifications` fails an event whose observation, acknowledgement or clearing is only among the records after the newest signed head (`unattested`), since anyone who can append to the stored trail could have written them. `-max-unattested` (library `MaxTailAge`) accepts such records, without a signature, when they are that recent. Leave it at zero unless your trail is signed on a schedule you can bound.
- **`-strict` can fail where the default passes.** `bide audit notifications -strict` fails on the warnings `unobserved_resolved` (a decided gate, or a halt resolved with `ResolveHalt`, that no notifier observed) and `all_clear_untimed` (a resolution the journal does not time, as in a journal an earlier version wrote), so journals that pass without `-strict` can fail with it. <!-- pending #283: check this item against #283's merged wording. -->
- **Decision records are named by the decision.** `agent.SubmitDecision` names a decision's journal step by the call, approver, verdict, scheme and decision time, not by its signature bytes, so a decision re-signed with a randomized scheme (ECDSA P-256) is journaled once. Journals written under the old names read, count and verify unchanged. `agent.DecisionStep` returns the new name; find the record that holds a decision with `agent.HeldDecisionStep`.
- **Stricter opens.** A Postgres store whose tables were altered (extra constraints, triggers, row-level security, other column types) is refused at open. `store/sqlite` and `govern/sqlitelog` open the canonical path and refuse a database file with more than one hard link. `signer/pkcs11` with `RequireNonExtractable` also refuses a key that was ever extractable or not sensitive, and a PIN shorter than four characters. `signer/awskms` refuses a `GetPublicKey` answer that names another key.
- **Evidence v6.** `bide.audit.evidence.v6` seals the SHA-256 of the package. A v5 package still verifies under its original seal, and `Seal` refuses to re-seal one.
- **A plan flow records its principal.** A flow run journals the principal of the identity it runs under, and a later drive under another principal is `ErrConfig`; a flow run recorded with none keeps none.
- **New webhook kinds.** The notifier now also posts `resolved` and `escalated` notifications. A receiver that treats every POST as a new alert should filter on `kind`.

Upgrading:

- Finish or resolve runs before upgrading, as with every pre-release. Turning on `ExcludePrincipal` for a gate whose tally already passed makes that gate ask again for approvals that exclude the requester.
- Webhook receivers: filter on `kind`, since `resolved` and `escalated` notifications now arrive beside the events they relate to.
- On Postgres, give the application role no `CREATE` on the schema and run `bide migrate -postgres-env VAR -schema S` as the owner; see the [Postgres guide](https://github.com/bide-ai/bide/blob/v0.17.0/docs/guides/postgres.md).
- An organization that hosts the approve page checks the files it serves against the release's signed `approve-page.SHA256SUMS` before each deploy.
