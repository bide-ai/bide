**Runs you can steer, cancel and recover exactly as they started.**

v0.10.0 completes the engine half of the pre-1.0 redesign. A run takes a `Message` and per-run options, journals them when it starts, and every later drive (a recovery drive included) runs under them. Runs can be cancelled and inspected from the journal, tools are described by one specification, construction is checked when the agent is built, and recovery hands each run to the code that knows how to drive it. Four new TLA+ models check the tool-call state machine, the run lifecycle, delegation and sessions, and P14's contract is written rule by rule against them.

- **One run entry point, with options that survive recovery.** `RunMessage`, `ResumeRun`, `StreamMessage` (with `AgentStream.Result()`), `RunTypedMessage[T]` (a Go 1.27 generic method) and `Session.SendMessage`/`SendMessageOnce` take a `Message` input, so a run can start from text and images, and return a `Result` on every outcome once the run ID is valid: an answer, a pause, a halt, a failure, a saga's abort or a cancellation. The run's input and options (turn limit, token budget, system prompt, sampling, tool choice, saga, tool filter, output mode, typed schema, principal) are journaled in `run:start`, and every later drive runs under them. A later drive may raise or lower a limit, journaled as an amendment; any other different setting is `ErrConfig` before any model call. These are the transitional names of the 1.0 API, which the rewrite renames `Run`, `Resume`, `Stream`, `RunTyped`, `Send` and `SendOnce`.
- **Cancel and Status.** `agent.Cancel(ctx, j, runID, reason)` stops a run at its next check: when a drive starts, at every turn boundary and after each won side-effect claim, so no side effect fires under a claim won after the cancellation. A cancelled saga rolls back first and then ends `run:cancelled`. A sub-agent's run, a programmatic sub-run and a delegation read their tree root's cancellation, so cancelling the root stops the whole tree, and `plan` flows honour `Cancel` too. The first end marker in journal order is a run's end for every reader. `agent.Status` reports a run's state (`RunState`) from one `Load`.
- **A per-run tool filter, enforced at dispatch.** `WithToolFilter(names...)` restricts a run to some of the agent's tools. It is journaled with the run and checked when each call is dispatched, so a call outside it records an error result and never runs, on the first drive and on every resume. `WithToolChoice(ToolChoice{Mode: "none"})` is enforced the same way.
- **Recovery that knows what it is resuming.** `Recover` and `RecoverLoop` read each run's `run:start` under its lease and pass it to an `agent.Resumer`. `ResumeAgent(a)` drives an agent's plain runs and sagas, `ResumeTyped[T](a)` its typed runs, and `ResumeAny` combines them with your own. A run that has not started yet, or that no `Resumer` drives, is reported once per process and read again on every pass. `RecoverLoop` runs a second loop that takes over only runs whose lease has lapsed, so a dead holder's run is picked up within about one interval however many halted runs the store holds, and `Leaser.ReapLeases` clears the leases no pass will take over. A recovery pass is cheaper than before although it reads every driven run's start.
- **Tools described by one specification.** `agent.ToolSpec` holds everything the agent knows about a tool (name, title, description, input and output schemas, safety, approval gate, timeout), read once when the tool is registered. Tool options set it: `WithApproval`, `WithTimeout`, `WithTitle`, `WithOutputSchema` and `WithSafety`. `Safety` is plain, comparable data (`ReadOnly`, `Idempotent`), the approval gate has its own field, with `agent.SingleApproval()` for one decision and `ApprovalPolicy` for m-of-n, and both are journaled with each tool result, so a saga rollback reads what the call ran under. Tool middleware receives an `agent.ToolCall` (`Use`, `Spec`, `RunID`). MCP tools gain `mcp.WithApproval`, their title, their output schema and their timeout.
- **Tool timeouts and tool calls that never misreport.** `WithTimeout` bounds a call, middleware included. A late result is recorded; a late error has an unknown outcome, so a side effect halts on resume rather than record a failure for an effect that may have landed. Each call's state is tracked by compare-and-swap: a side effect whose tool began and did not itself fail is never recorded as a known failure, a result needs positive proof that no invocation is still running, and no invocation of `next` begins the tool after the chain has returned. `ErrToolNotCalled` marks a call known never to have reached its tool, and `SagaAborted.UnknownOutcome` lists saga steps that may have committed.
- **Construction checked when the agent is built.** `agent.Build(model, journal, opts...)` and `Agent.With(opts...)` return every configuration problem as `ErrConfig` up front: nil parts, duplicate or reserved tool names, a tool name the model's provider refuses (`ToolRules`, declared by the OpenAI, Anthropic and Gemini adapters), non-object schemas, invalid approval policies and negative limits. Option scopes are interfaces, so an option passed where it does not apply does not compile. Decorators that hide a tool's approval gate or timeout are refused unless they implement `Spec` or `Unwrap`.
- **Programmatic sub-runs that a saga's rollback reaches.** `agent.RunInfoFrom(ctx)` describes the tool call a context belongs to, and `RunInfo.SubRunFor(name)` names a sub-run started from that call. With `WithSubRuns`, a saga links each such sub-run in its journal before the sub-run writes anything, and its rollback compensates the sub-run's writes with the declared agent's compensators, latest first.
- **Retrieval as a journaled engine step.** `WithRetrieval(r, k)` is an agent option: the agent retrieves for the run's user message once, journals the documents, and every model middleware sees the request with them in it. `WithRetrievalRetry` retries a failed retrieval with backoff and full jitter, recording only the attempt that succeeded.
- **Delegation that rolls back under its own authority.** A saga whose delegations were minted under several grants (a root grant rotated or expired between drives) rolls back with all of them bound (`audit.WithRollbackGrants`), each child grant verified against its own parent. A delegation's rollback keeps the grant's expiry guard, and the rollback walks a sub-agent's run whatever the call's result.
- **Sessions under a lease.** Over a store with leases, one worker drives a session turn at a time, so a turn under `WithTokenBudget` spends its budget once. Another worker returns the turn's recorded answer, or `ErrTurnContended` while it runs. A stale handle reads the journal before it refuses a new message, two callers on one handle record a turn once, and a cancelled turn is closed by the next message's `Send`.
- **Four new TLA+ models, with the code kept in step.** Model 9 checks the tool-call state machine, model 10 the run lifecycle and recovery, model 11 delegation, sub-run authority and saga trees, and model 12 sessions, all under store faults, crashes and cancellations. Between them they found T1 to T6, L1 to L7, D1 to D3 and S1 to S4, and every one is fixed in this release and kept as a regression configuration. Model 10 was extended to state P14's rules before any of P14's code was written, and P14 implements a 16-rule contract from models 10 and 12, each rule with a test committed failing before its code. Code the models describe carries region markers, and CI (`modelsync`) fails a change to marked code that leaves its model unchanged without saying why. The required Models job takes about 6 minutes, and the larger configurations run nightly. [Formal verification](https://github.com/bide-ai/bide/blob/main/docs/formal-verification.md) gives an overview of every model, what it guarantees and every bug it caught.

API changes:

- `agent.Recover` and `agent.RecoverLoop` take an `agent.Resumer`, `func(ctx, runID string, start RunStart) error`; use `agent.ResumeAgent(a)`.
- `RunStart.Input` is a `Message`; `Sampling` and `ToolChoice` marshal with snake_case JSON names.
- Typed runs journal their typed start, so a typed run resumes through `RunTypedMessage` or `ResumeTyped`, not `Run`.
- A run's first end marker in journal order is its end; `ErrNotStarted` wraps no category.
- A finished run returns its recorded answer only to a drive with the input its `run:start` recorded.
- `Safety` is `{ReadOnly, Idempotent}`: the approval gate is `WithApproval(SingleApproval())` or `WithApproval(&ApprovalPolicy{...})`, and `Safety.IdempotencyKey`, `RequiresApproval` and `Approval` are removed. `ApprovalPolicy` literals need field names, and one with no approvers is `ErrConfig`.
- `ToolHandler` is `func(ctx, ToolCall) (json.RawMessage, error)`; middleware passes `next` the call it was given. `ToolSafety`, `WithToolSafety` and `ToolErrorText` are removed.
- `Request.Tools` is `[]ToolSpec` and `ToolsDigest` takes `[]ToolSpec`; tool-result records carry `Safety` and `Approval` instead of `ReadOnly`.
- `govern.EventTool`, `govern.FederatedEventTool` and `audit.AttenuatingSubAgent` take config structs; `govern.AttestedEventTool` is removed.
- `mcp.WithSafety` sets only `ReadOnly` and `Idempotent` (gate with `mcp.WithApproval`), and `mcp.Tools` refuses a non-object `outputSchema`.
- Tool decorators that hide an approval gate or timeout, wrappers that are also `Compensator`s, and sub-agent wrappers with their own `Timeout` or `Safety` are `ErrConfig`; invalid tool options panic with `ErrConfig`.
- `SagaAborted.UnknownOutcome` lists saga steps that may have committed; a side effect that began is never recorded as a known failure.
- `RunFilter.Admits` takes a `lapsed` function, and `Leaser` has `ReapLeases`.
- `Record`'s model-turn fields (`Finish`, `RawFinish`, `Model`, `PromptDigest`, `ToolsDigest`) and approver fields (`Approver`, `ApproverAlg`, `Signature`) move behind `*ModelTurn` and `*ApproverSignature`; read them with the methods of the same names.
- `WithRetrieval` is an agent option, `RetrievalTool` takes a name and description, and `trace.Instrument` returns an agent option.
- The context decorators are `ContextWithIdentity`, `ContextWithWaker` and `ContextWithClock`; the `With` names are agent and run options. `WithNow` is `WithClock` and `StepSafety` is `WithSafety`.
- `Parallel` takes its tasks as a slice and its cap as `WithMaxConcurrency(n)`; `Lease`, `Recover` and `RecoverLoop` take their own option types.
- `RunScope` and `InSaga` are replaced by `RunInfoFrom`; a plain run started from a saga's tool call is not a saga.

## Migrating from v0.9.0

Each breaking change, with the v0.9.0 form and the v0.10.0 form. The deprecated entry points (`Agent.Run` with a string, `RunSaga`, `Stream`, `RunTyped`, `Session.Send` and `SendOnce`, `agent.New` and its builder methods) still work in v0.10.0; the 1.0 rewrite removes them.

### Recovery takes a Resumer

`Recover` and `RecoverLoop` pass each run's journaled start to a `Resumer`. `ResumeAgent` drives a run under the options its first drive journaled, so the callback no longer needs the input.

<!-- docsnip: skip v0.9.0 API -->
```go
n, err := agent.Recover(ctx, store, func(ctx context.Context, runID string) error {
	_, err := a.Run(ctx, runID, inputFor(runID))
	return err
})
```

<!-- docsnip: setup ctx context.Context; store agent.Durable; a *agent.Agent; w agent.Waker; type Invoice struct{ Total float64 } -->
```go
n, err := agent.Recover(ctx, store, agent.ResumeAny(
	agent.ResumeAgent(a, agent.WithWaker(w)),
	agent.ResumeTyped[Invoice](a, agent.WithWaker(w)),
))
```

A callback of your own takes the start as a third parameter:

<!-- docsnip: setup ctx context.Context; store agent.Durable; func drive(ctx context.Context, runID string, start agent.RunStart) error -->
```go
err := agent.RecoverLoop(ctx, store, func(ctx context.Context, runID string, start agent.RunStart) error {
	return drive(ctx, runID, start)
})
```

### RunStart.Input is a Message

A text input is still journaled as a JSON string, so existing records read back unchanged.

<!-- docsnip: skip v0.9.0 API -->
```go
var text string = start.Input
```

<!-- docsnip: setup start agent.RunStart -->
```go
text := start.Input.Text()
```

### Sampling and ToolChoice JSON

Code that encodes or decodes these types itself sees snake_case names, as `run:start` journals them.

```json
{"Temperature": 0.2, "MaxTokens": 512}
{"Mode": "tool", "Name": "lookup"}
```

```json
{"temperature": 0.2, "max_tokens": 512}
{"mode": "tool", "name": "lookup"}
```

### Typed runs resume as typed runs

`RunTyped` and `RunTypedNative` journal the output mode and the answer type's schema, so a typed run started under v0.10.0 is resumed with `RunTypedMessage` or `ResumeTyped` of the same type. Resuming it through `Run`, or with another type, is `ErrConfig`.

<!-- docsnip: skip v0.9.0 API -->
```go
answer, err := a.Run(ctx, runID, input) // resumed a typed run as a plain one
```

<!-- docsnip: setup ctx context.Context; a *agent.Agent; runID, input string; type Invoice struct{ Total float64 } -->
```go
inv, res, err := a.RunTypedMessage[Invoice](ctx, runID, agent.UserText(input))
```

### The first end marker is the run's end, and ErrNotStarted has no category

A run whose `run:cancelled` precedes its `run:complete` returns `ErrRunCancelled`, not its answer, and `IsComplete` reports it not complete. `ErrNotStarted` no longer wraps `ErrConfig` (it is often a race with a run's first drive), so test for it by name.

<!-- docsnip: skip v0.9.0 classification -->
```go
if errors.Is(err, agent.ErrConfig) { // also caught ErrNotStarted
	return err
}
```

<!-- docsnip: setup err error; returns error -->
```go
switch {
case errors.Is(err, agent.ErrNotStarted):
	return nil // retry once the run's first drive has written run:start
case errors.Is(err, agent.ErrRunCancelled):
	return nil // the run's end, not a failure
}
return err
```

### A finished run answers only its own input

In v0.9.0 a finished run returned its answer to a drive with any input. It now needs the input its `run:start` recorded, as an unfinished run does; another input is `ErrConfig`. To read back a finished run's answer without its input, resume it:

<!-- docsnip: skip v0.9.0 behaviour -->
```go
answer, err := a.Run(ctx, runID, "") // any input read back the answer
```

<!-- docsnip: setup ctx context.Context; a *agent.Agent; runID string -->
```go
res, err := a.ResumeRun(ctx, runID) // res.Message is the recorded answer
```

### Safety and the approval gate

`Safety` is `{ReadOnly, Idempotent}`; the approval gate is a tool option. `ApprovalPolicy` has an unexported field, so name its fields. Only `SingleApproval()` asks for the one-decision gate; a policy with no approvers (`{Need: 1}` included) is `ErrConfig`.

<!-- docsnip: skip v0.9.0 API -->
```go
refund := agent.Func("refund", "Refund an order.", agent.Safety{RequiresApproval: true}, refundOrder)
transfer := agent.Func("transfer", "Move funds.",
	agent.Safety{Approval: &agent.ApprovalPolicy{2, []string{"alice", "bob", "carol"}}}, moveFunds)
```

<!-- docsnip: setup type Order struct{ ID string }; func refundOrder(context.Context, Order) (string, error); func moveFunds(context.Context, Order) (string, error) -->
```go
refund := agent.Func("refund", "Refund an order.", agent.Safety{}, refundOrder,
	agent.WithApproval(agent.SingleApproval()))
transfer := agent.Func("transfer", "Move funds.", agent.Safety{}, moveFunds,
	agent.WithApproval(&agent.ApprovalPolicy{Need: 2, Approvers: []string{"alice", "bob", "carol"}}))
```

`Safety.IdempotencyKey` is removed: `Idempotent` says the same, and the tool derives its downstream key from its arguments or from `NextOnceKey`.

<!-- docsnip: skip v0.9.0 API -->
```go
s := agent.Safety{Idempotent: true, IdempotencyKey: func(args json.RawMessage) string { return string(args) }}
```

<!-- docsnip: setup ctx context.Context -->
```go
s := agent.Safety{Idempotent: true}
key := agent.NextOnceKey(ctx) // inside the tool: one key per tool call
```

### Tool middleware receives a ToolCall

A `ToolHandler` takes an `agent.ToolCall`. Read the tool's spec from `call.Spec` and the error text from `call.ErrorText`; nothing about the tool travels in the context. Pass `next` the call you were given, or a copy with other `Use.Args`: a call with another `Use.Name` or `Use.ID`, or one built by hand, is `ErrConfig`.

<!-- docsnip: skip v0.9.0 API -->
```go
logWrites := func(next agent.ToolHandler) agent.ToolHandler {
	return func(ctx context.Context, use agent.ToolUse) (json.RawMessage, error) {
		if s, _ := agent.ToolSafety(ctx); !s.ReadOnly {
			log.Printf("write: %s", use.Name)
		}
		out, err := next(ctx, agent.ToolUse{ID: use.ID, Name: use.Name, Args: redact(use.Args)})
		if err != nil {
			log.Printf("%s failed: %s", use.Name, agent.ToolErrorText(ctx, use.Name, err))
		}
		return out, err
	}
}
```

<!-- docsnip: setup func redact(json.RawMessage) json.RawMessage -->
```go
logWrites := func(next agent.ToolHandler) agent.ToolHandler {
	return func(ctx context.Context, call agent.ToolCall) (json.RawMessage, error) {
		if !call.Spec.Safety.ReadOnly {
			log.Printf("write: %s", call.Use.Name)
		}
		call.Use.Args = redact(call.Use.Args)
		out, err := next(ctx, call)
		if err != nil {
			log.Printf("%s failed: %s", call.Use.Name, call.ErrorText(err))
		}
		return out, err
	}
}
```

### MCP approval and output schemas

<!-- docsnip: skip v0.9.0 API -->
```go
tools, err := mcp.Tools(ctx, session, mcp.WithSafety("delete_file", agent.Safety{RequiresApproval: true}))
```

```go

	mcp.WithSafety("read_file", agent.Safety{ReadOnly: true}),
```

`mcp.WithApproval` fails `Tools` with `ErrConfig` when the server lists no tool of that name. `Tools` fails with `ErrProtocol` when a server lists a tool whose `outputSchema` is not an object schema. `WithCallTimeout` also sets each tool's `ToolSpec.Timeout`, so an error the server reports after the deadline has an unknown outcome under the agent's timeout rule.

### Tool decorators and wrappers

A decorator that embeds a tool has no `Spec` method of its own, so the agent refuses it (`ErrConfig` at `Build`, `New` and plan's tool check) when the tool inside has an approval gate or a timeout its own spec lacks. Keep the gate by implementing `Unwrap` (or `Spec`):

<!-- docsnip: setup import "log" -->
```go
type logged struct{ agent.Tool }

func (l logged) Call(ctx context.Context, args json.RawMessage) (json.RawMessage, error) {
	log.Printf("calling %s", l.Name())
	return l.Tool.Call(ctx, args)
}

// Unwrap lets the agent read the wrapped tool's approval gate and timeout.
func (l logged) Unwrap() agent.Tool { return l.Tool }
```

A wrapper that is also a `Compensator`, and one around a sub-agent with its own `Timeout` or `Safety`, is `ErrConfig`. `SubAgent` takes `WithApproval` and refuses `WithSafety` and `WithTimeout`.

### Saga steps with an unknown outcome

A saga step that failed with an unknown outcome (a retry-safe step that returned `ErrToolOutcomeUnknown`, or an error after its deadline) may have committed. The rollback lists it rather than take it for a step that changed nothing, and does not run its compensator on a result it never returned:

<!-- docsnip: setup err error -->
```go
var aborted *agent.SagaAborted
if errors.As(err, &aborted) {
	for _, step := range aborted.UnknownOutcome {
		log.Printf("check by hand, may have committed: %s", step)
	}
}
```

No code change is needed for the two related rules: a side effect whose tool began and did not itself fail is never recorded as a known failure (the run halts instead), and a result returned while an invocation of the tool is still running has an unknown outcome.

```go

	log.Printf("answered by %s", rec.Model.Model)
}
approver := rec.Approver
fake := agent.Record{Finish: agent.FinishStop, PromptDigest: digest}
```

```go
if rec.Finish() == agent.FinishStop && rec.Model() != nil {
	log.Printf("answered by %s", rec.Model().Model)

approver := rec.Approver()
fake := agent.Record{ModelTurn: &agent.ModelTurn{Finish: agent.FinishStop, PromptDigest: digest}}
```

### Retrieval, tracing and construction

`WithRetrieval` is an agent option, retrieved and journaled once per run before the model middleware. `middleware.Retry` no longer retries a failed retrieval (use `WithRetrievalRetry`), and a policy that must keep a query from the store wraps the `Retriever` (`agent.RetrieverFunc`).

<!-- docsnip: skip v0.9.0 API -->
```go
a.Use(agent.WithRetrieval(docs, 5))
search := agent.RetrievalTool(docs, 5,
	agent.RetrievalName("search_docs"), agent.RetrievalDescription("Search the product docs."))
a = trace.Instrument(a, tracer)
```

<!-- docsnip: setup model agent.Model; j *agent.Journal; docs agent.Retriever; import oteltrace "go.opentelemetry.io/otel/trace"; tracer oteltrace.Tracer -->
```go
search := agent.RetrievalTool("search_docs", "Search the product docs.", docs, 5)
a, err := agent.Build(model, j,
	agent.WithTools(search),
	agent.WithRetrieval(docs, 5, agent.WithRetrievalRetry(3, 100*time.Millisecond, 2*time.Second)),
	trace.Instrument(tracer))
```

On an existing agent, `a.With(...)` returns a configured copy.

### Context decorators and renamed options

The `With` names are agent and run options; the context decorators are `ContextWith...` (transitional). A value bound to the run's context takes precedence over the agent's option. `WithNow` is `WithClock`, `StepSafety` is `WithSafety`, and `WithClock(nil)` is `ErrConfig`.

<!-- docsnip: skip v0.9.0 API -->
```go
ctx = agent.WithIdentity(ctx, agent.Identity{Actor: "billing-svc"})
ctx = agent.WithWaker(ctx, w)
err := agent.ResolveHaltRef(ctx, store, ref, out, agent.WithNow(now))
v, err := agent.Step(ctx, store, runID, "charge", charge, agent.StepSafety(agent.Safety{Idempotent: true}))
```

<!-- docsnip: setup ctx context.Context; model agent.Model; j *agent.Journal; store agent.Durable; w agent.Waker; ref agent.HaltRef; out agent.Outcome; now func() time.Time; runID string; charge func(context.Context) (string, error) -->
```go
a, err := agent.Build(model, j,
	agent.WithIdentity(agent.Identity{Actor: "billing-svc"}), agent.WithWaker(w))
ctx = agent.ContextWithIdentity(ctx, agent.Identity{Actor: "billing-svc"}) // per call, where needed
err = agent.ResolveHaltRef(ctx, store, ref, out, agent.WithClock(now))
v, err := agent.Step(ctx, store, runID, "charge", charge, agent.WithSafety(agent.Safety{Idempotent: true}))
```

### Parallel, Lease and Recover options

<!-- docsnip: skip v0.9.0 API -->
```go
results, err := agent.Parallel(ctx, store, runID, 4, t1, t2)
n, err := agent.Recover(ctx, store, resume, agent.WithRecoverInterval(time.Second)) // ignored
```

<!-- docsnip: setup ctx context.Context; store agent.Durable; runID string; t1, t2 agent.Task[string]; resume agent.Resumer -->
```go
results, err := agent.Parallel(ctx, store, runID, []agent.Task[string]{t1, t2}, agent.WithMaxConcurrency(4))
err = agent.RecoverLoop(ctx, store, resume,
	agent.WithRecoverInterval(time.Second), agent.WithLeaseTTL(30*time.Second))
```

`WithLeaseHolder` and `WithLeaseTTL` fit `Lease`, `Recover` and `RecoverLoop`; `WithRecoverInterval`, `WithRecoverConcurrency`, `WithRecoverErrors` and `WithRecoverLapsedConcurrency` fit only `RecoverLoop`.

### RunInfo replaces RunScope and InSaga

<!-- docsnip: skip v0.9.0 API -->
```go
childID := agent.SubRunID(agent.RunScope(ctx), use.ID)
if agent.InSaga(ctx) {
	journalArgs()
}
```

<!-- docsnip: setup ctx context.Context; func journalArgs() -->
```go
info, _ := agent.RunInfoFrom(ctx)
childID := agent.SubRunID(info.RunID, info.ToolUseID)
if info.Saga {
	journalArgs()
}
```

Whether a call is in a saga is its own run's flag. A plain run started from a saga's tool call (with a `SubRunFor` ID) is not a saga; start it with `RunSaga` to keep it one:

<!-- docsnip: setup ctx context.Context; child *agent.Agent; input string -->
```go
info, _ := agent.RunInfoFrom(ctx)
answer, err := child.RunSaga(ctx, info.SubRunFor("charge"), input)
```

A programmatic sub-run is refused once the call that names it has returned. In a saga, its name is at most 96 bytes once escaped, and it journals to the saga's store.

## Upgrading journals across the pre-release

Before 1.0, a run is not promised to resume across releases: every pre-release writes the journal format tag `bide.journal.v1-dev`, and the tag is not bumped when keys or the record shape change. Finish or resolve runs before upgrading. From v0.9.0 to v0.10.0, three cases need attention when runs are in flight across the upgrade:

- **Runs started by v0.9.0 (legacy `run:start`).** v0.10.0 writes the kind of every run it starts. A `run:start` written by v0.9.0 has no kind and no typed start, and any agent entry point still drives it as before: a session turn, a `SendOnce` turn or a typed run resumes through its session or `RunTypedMessage`. Recovery does not guess between a plain run and a typed one, so `ResumeAgent` and `ResumeTyped` return `ErrNotResumable` for such a run, and `Recover` reports it once per process.
- **Typed runs from v0.9.0 need a Resumer of your own.** Finish them before upgrading, or recover them with a `Resumer` that knows which entry point started each run, after `ResumeAgent` in `ResumeAny`:

  <!-- docsnip: setup ctx context.Context; store agent.Durable; a *agent.Agent; type Invoice struct{ Total float64 }; func isInvoiceRun(runID string) bool -->
  ```go
  legacy := func(ctx context.Context, runID string, start agent.RunStart) error {
  	if start.Kind != "" || start.Typed != nil {
  		return agent.ErrNotResumable // started by v0.10.0: ResumeAgent or ResumeTyped drives it
  	}
  	if isInvoiceRun(runID) { // your own record of which runs were typed
  		_, _, err := a.RunTypedMessage[Invoice](ctx, runID, start.Input)
  		return err
  	}
  	_, err := a.ResumeRun(ctx, runID)
  	return err
  }
  n, err := agent.Recover(ctx, store, agent.ResumeAny(agent.ResumeAgent(a), agent.ResumeTyped[Invoice](a), legacy))
  ```

- **Finished runs refuse a different input (R137-2).** A finished run returns its recorded answer only to a drive with the input its `run:start` recorded. In v0.9.0 it answered any input, so a `SendOnce` key reused for another message, whose run had finished and was not yet recorded, was answered with the first message's reply. Code that re-drove finished runs with a placeholder input reads them back with `ResumeRun` instead (see the migration above).

Two more journal changes: tool results journaled by v0.9.0 carry no `safety`, so a saga rollback over them treats every completed call as a write; and a saga journaled by v0.9.0 that holds an ungranted `audit.AttenuatingSubAgent` delegation cannot be rolled back after the upgrade (the rollback stops with `ErrProtocol` rather than guess), so finish or roll back such sagas first. On Postgres, `Open` creates two indexes on the leases table when they are missing; on a store whose role does not own the tables, the owner opens it once to create them.
