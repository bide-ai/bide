**Edit a flow's approval gates in the browser, and keep a certificate-bound gate's CRLs current without writing the loop yourself.**

v0.20.0 completes the first phase of the flow editor and adds a CRL refresher for certificate-bound approvers. `bide edit flow.yaml` now lets a policy owner change a node's safety, block and approval gate with forms, build assertions from templates, see at once whether an edit weakens the flow, and save the file with a reviewed diff. The new `audit/crlrefresh` package (experimental) fetches, verifies, archives and monitors the CRLs a gate's status check reads, and `bide identity fetch-crl` runs the same code from cron or as a daemon.

- **`bide edit` is an editor.** The page runs on a loopback address and edits the file `plan` reads, with the verdict of `bide check` shown as you work. See the [flow editor guide](https://github.com/bide-ai/bide/blob/v0.20.0/docs/guides/flow-editor.md).
  - *Forms.* A node's safety, block and approval gate (decisions needed, approvers in order, `exclude_principal`, deadline) are forms. Each change is a verified splice of the file's text, so the diff of an edit is the edit and comments, key order and blank lines stay. Each draft is checked by the server and its answer is shown in the check's own words; undo and redo restore the exact earlier text.
  - *Assertions.* The panel lists the `assert` lines with their verdicts and counterexample paths, and adds, edits and removes them from the six forms of the grammar. The verdict of a new line is shown before it is added.
  - *Baseline compare.* The file is compared with the committed policy (git `HEAD`, or `-base <rev>`) by the classifier that `bide check -diff -check -fail-on-weaken` runs. A text that weakens an approval gate or a safety check shows a banner with no close control, announced as an alert, until the text no longer weakens.
  - *Source edit and save.* Edit the source directly and the graph, outline, assertions and problems follow. Save opens a dialog with the unified diff, the comments the edit removes and the items to confirm for a weakening; the server refuses a save without exactly that confirmation. The write is atomic, and a file that changed on disk since it was read is a conflict, shown against your text and never overwritten.
  - *Accessibility.* The outline is one Tab stop, the drawing's nodes are buttons named by their details, and the save dialog returns focus. A Chrome test drives the whole path by keyboard alone and axe-core runs over the page in light and dark in five states. A manual screen-reader pass has not been done yet; the guide lists what to check by hand.
- **A CRL refresher for certificate-bound approvers (experimental).** `crlrefresh.New(approver, sources, opts)` keeps the approver's `StatusSnapshot` supplied with the newest CRLs of the issuers the policy pins, using `Run` or `RefreshOnce` from cron. It fetches only from the URLs the policy names, over HTTP or HTTPS, verifies each CRL against its issuer before adding it, refuses a rollback or an equivocating same-number CRL, pairs delta CRLs with their base, and archives every accepted CRL in a dated series it rebuilds its state from at start. It never makes status look fresher than the CRL's own dates say. `Health()` reports each issuer's age and next expected CRL, and an alarm is computed from the CA's declared period and the gate's own freshness limit. The [certificate approvers guide](https://github.com/bide-ai/bide/blob/v0.20.0/docs/guides/certificate-approvers.md) has the setup, the sizing of the alarm and advice on the root CRL's validity.
- **Commands for the archive.** `bide identity fetch-crl` runs the refresher for cron (`-once`) or as a daemon, `bide identity reset-high-water` and `ack-reset` are the audited way out of a CA's mistaken, very high CRL number. `bide approve -cert` still fetches nothing.
- **Assertion names are read as written.** A node name in double quotes in an `assert` line is now read raw, by the check, by `RenameAssertion` and `CompareAssertions`, and by the editor, which writes the same lines. See the upgrade note below.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.20.0

API changes:

- Added: package `audit/crlrefresh` (`New`, `Refresher.Run`, `RefreshOnce`, `Health`, `DirArchive`, `Options`, `Hooks`; stability label experimental), and the commands `bide identity fetch-crl`, `reset-high-water` and `ack-reset`. The generated [API reference](https://github.com/bide-ai/bide/blob/v0.20.0/docs/reference/api/index.md) lists every new symbol.
- Added, in module `flowedit` (experimental): `flowedit.ApplyOperation`, `Assertion` and `Assertion.Text`, `ParseAssertion`, `Compare`, `WithBase`, `(*Server).Preview`, `(*Server).Save`, `UnifiedDiff`, `RemovedComments` and `Node.Approval`; `bide edit` gains `-base <rev>`.
- Changed: a quoted node name in an `assert` line is read without escapes (upgrade note below).

Upgrading:

- If an `assert` line relied on an escape inside quotes (`"café"`), it now names a different node: write the character itself (`"café"`). `bide check` warns on every quoted name that contains a backslash sequence the old reading would have changed, so no assertion silently starts naming another node.
- Nothing else changes for existing flows and gates. The CRL refresher is opt-in, and `bide edit` writes only the file named on the command line, after you confirm a save.
