**A fix for `agent.ClaimAttempt`'s `AttemptedAt` clock, which v0.23.1 got wrong.**

v0.23.2 is a patch of v0.23.1. It holds one change and nothing from the v0.24.0 work.

- **Fixed: `ClaimAttempt` stamps `AttemptedAt` from the wall clock again.** v0.23.1 stamped it from the clock bound to the context (`WithClock`), the run clock. That was a mistake: the engine's own claims for a tool call and a `Journal.Step` were always stamped from the wall clock, and the age checks compare against the wall clock.

Who was affected in v0.23.1: an agent whose `WithClock` runs behind the wall clock, and that uses `ClaimAttempt` markers together with `ResolveHalt` `WithMinHaltAge` or the notifier. A marker claimed that instant then looked old. `ResolveHalt` with `WithMinHaltAge` could resolve a halt on such a marker at once, despite the minimum age, and the notifier's sweep reported it as a halt before `WithNotifyHaltAge`, so the ages it reported were off too.

v0.23.2 restores the wall clock. Without `WithClock` nothing changes. The v0.23.1 hardening is kept: `ClaimAttempt` still refuses everything but a bare attempt marker, and a caller still cannot set `AttemptedAt`.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.23.2

API changes:

- None. No name is added, removed or renamed.

Upgrading:

- Upgrade if you run an agent on a `WithClock` behind the wall clock and use `ClaimAttempt` markers with `WithMinHaltAge` or the notifier. Nothing else changes.
