**bide now speaks GCF.**

Agents push the same structured tool output across the model boundary every turn. With v0.2.0, bide can encode those tool results as [GCF](https://gcformat.com), the Graph Compact Format, instead of JSON: a compact, lossless wire format for structured data, designed to be read by frontier models with no training.

bide encodes each tool result on its own (per-payload), which trims the tokens spent echoing structured output back to the model. GCF's largest wins come from deduplicating repeated structure and sending deltas across a multi-turn session, that is a GCF capability bide does not wire in yet. For the benchmarks and the full multi-turn story, see [gcformat.com](https://gcformat.com).

It is opt-in per model adapter and changes only what the model reads. The journal and the RFC 6962 audit trail keep the canonical JSON, so durability and proofs are untouched, and if a result ever fails to encode the adapter falls back to JSON.

<!-- docsnip: setup apiKey string -->
```go
import (
    "github.com/bide-ai/bide/model/openai"
    "github.com/bide-ai/bide/codec/gcf"
)

model := openai.New(apiKey, openai.WithToolResultCodec(gcf.New()))
```

The same `WithToolResultCodec` option is on the Anthropic and Gemini adapters. GCF lives in its own module (`github.com/bide-ai/bide/codec/gcf`), so the core takes no GCF dependency unless you opt in.

Everything from v0.1.0 stands: at-most-once side effects, HA in a single process, a verifiable Merkle audit trail, and provably convergent state.

Install:

    go get github.com/bide-ai/bide@v0.2.0
