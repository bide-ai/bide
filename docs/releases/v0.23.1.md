**A security fix for `agent.ClaimAttempt`, and a cap reconcile clock fix.**

v0.23.1 is a patch of v0.23.0. It holds those two changes and nothing from the v0.24.0 work.

- **Security: `agent.ClaimAttempt` claims bare attempt markers only.** v0.23.0 and earlier let a caller with journal access write other records through it, because the journal stores whatever record it is given. Affected: an application, or anyone who can call `ClaimAttempt` against a journal. What a caller could plant: a tool result under a name of its own (the next drive of a halted call completed with the forged result and never ran the tool); a single-approver approval (the next drive ran the gated tool; an m-of-n gate was never affected, since only signed decisions count); a record under a name the engine reserves, such as a `cap-intent:` that pinned a cap reservation to an old window and so bypassed the cap, a `gate-reason:` or an `approval-pending:`; a marker with a back-dated `AttemptedAt`, so a halt looked old enough for `ResolveHalt`'s `WithMinHaltAge`.
- **Fixed: the cap reconcile pass reads the context's clock.** `Recover` and `RecoverLoop` read the wall clock to decide whether a day or hour window was still open, while a run reserves by its own clock. They now read the clock bound to their context, else the wall clock. No application could bind one to `Recover`, so a deployment saw no change in behavior; the wall-clock judgement and its over-count direction for `WithClock` agents are documented in `Recover`, `RecoverLoop` and the [known limitations](https://github.com/bide-ai/bide/blob/v0.23.1/docs/KNOWN-LIMITATIONS.md).

What `ClaimAttempt` refuses now, with `ErrConfig` and no write:

- a name under a reserved prefix (`cap-intent:`, `cap-reserve:`, `gate-reason:`, `approval-pending:`, `slot:`, `taint/` and the rest that `Step` refuses), except `attempt:`;
- the engine-derived `attempt:not-started:` and `attempt:retry:` names, and an empty name;
- a record whose kind is not `attempt`, or an attempt record that carries a result, an approval, a model turn, a reconciliation or evidence;
- a caller-set `AttemptedAt`. The claim stamps it from the context's clock.

The engine's own paths (the halt resolution's claim included) do not use the exported call and are unchanged.

Not changed, and stated in the [known limitations](https://github.com/bide-ai/bide/blob/v0.23.1/docs/KNOWN-LIMITATIONS.md): a caller with journal access can still pre-claim an `attempt:tool:<call>` marker. That halts the call (`OutcomeUnknown`), a denial of service in the safe direction. It cannot admit the call or release a cap, because only a not-started record that carries the marker's own claim id voids an attempt.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.23.1

API changes:

- Changed: `agent.ClaimAttempt` returns `ErrConfig`, and writes nothing, for anything but a bare attempt marker (above). No name is added, removed or renamed.

Upgrading:

- Upgrade. An application that called `ClaimAttempt` with a non-attempt record, a reserved name or a set `AttemptedAt` now gets `ErrConfig`; claim an attempt marker (`attempt:...`, `Kind: StepAttempt`, no other fields) instead.
- Nothing else changes.

The [CHANGELOG](https://github.com/bide-ai/bide/blob/v0.23.1/CHANGELOG.md) has the details.
