**Bound what an agent can do after it reads untrusted content, and show the approver why a call is held.**

v0.24.0 adds untrusted-content tainting. A run that read content a tool marked untrusted now needs an escalation gate, decided by its own approvers, for each later side-effecting call; the taint follows the run into sub-agents, sub-runs and session turns; and the reasons a call is held are shown to the person who decides it. It also adds a report on what an agent declares, an audit of the amount-cap ledgers, and an agent project scaffold. The new Go names (`WithTaintPolicy`, `TaintPolicy`, `Trusted`, `RequireProvenance`, `GateReason`, the `Why` fields, `Declarations`) and the new flags and commands are experimental: they may change in a minor release.

Tainting bounds the consequences of a request a model was steered into. It does not detect or prevent prompt injection, and an approver who reads a convincing injected justification and approves has been successfully attacked. Caps apply only to tools that carry a rule. The [known limitations](https://github.com/bide-ai/bide/blob/v0.24.0/docs/KNOWN-LIMITATIONS.md#untrusted-content-and-the-taint-policy) list what the policy leaves out.

- **Taint policy (experimental).** `agent.WithTaintPolicy(agent.TaintPolicy{...})` makes a run that read untrusted content need an escalation gate for each later side-effecting call (or, with `Refuse`, refuses it), in addition to the tool's own gate. The gate is a second instance on the call, under the subject `<call>#taint`, decided by its own approvers, and an approval clears nothing: the next call is asked again. Not gated: `ReadOnly` tools, a `TaintExempt` tool (visible in the declarations digest), a call requested in the same turn as the read of outside text (the model had not yet seen the content, so a tool that returns outside text and a side effect asked for in that same turn are not gated), and a saga's rollback. The recorded policy decides: a run is gated by the policy it started under, and the approvals intake, `bide approve`, `bide approve -list`, `bide view` and the audit evidence decide and show the instance by the gate the call's pause note records. See the [untrusted content guide](https://github.com/bide-ai/bide/blob/v0.24.0/docs/guides/untrusted-content.md).
- **Taint crosses run boundaries.** A sub-agent started by a call of a tainted turn records the marks that turn was shown (`ext.taint_inherited` in its `run:start`) and starts tainted. A sub-agent whose run ended with a mark marks the parent's `tool_result` for the call, so the parent's next turn is tainted. A session turn that ended with marks records them in the session journal, so every later turn starts with them. Runs not under a taint policy record and pass nothing, and their journals are as before. A saga's rollback re-run of a sub-agent, the answer `ResolveHalt` injects, and a run a tool starts by a path bide does not own carry no mark. Plan flow nodes are not covered.
- **Provenance required (experimental).** `agent.TaintPolicy.RequireProvenance` makes the policy refuse a tool that states no provenance: a tool must declare `agent.Untrusted` or the new `agent.Trusted(reason)` (`ToolSpec.Trusted` is the same declaration; the reason is required and goes in the declarations digest), else `agent.New` returns `ErrConfig` naming the tool. A new `Run`, `Send` or `SendOnce` must state `WithUntrustedInput` or `WithTrustedInput`, else `ErrConfig` at its first drive with nothing written. It declares; it does not verify: a `Trusted` reason is the host's word.
- **Declarations report and diff.** `(*Agent).Declarations` writes a document of the taint and cap declarations of an agent. `bide doctor -declarations <file>` reports on it (side-effecting tools with no taint policy, exempt tools, cap-carrying tools, a weak escalation gate), and `bide doctor -diff <old> <new>` lists every change between two dumps as weakened, changed or strengthened (a raised cap limit, a removed or renamed cap rule, a removed `Untrusted`, a new `TaintExempt`, a lower `need`, a requester no longer excluded, `RequireProvenance` turned off) and exits 1 if anything is weakened. It sees only what the host dumps; a tool behind a wrapper that hides its spec is not in it. A document with a member this version does not know, or whose digest is not the digest of what it declares, is refused.
- **Gate reasons.** `bide approve -list` and the decision screen print `why:` lines for a held call: the untrusted content its turn read, where, and at which journal position, or the cap rule that holds it with this call's figures. `bide view` shows them in the gate's card, `-list -json` carries `why`, the notifier payload carries `approval.why` (a cap reason's figures only for a tool named in `Args(...)`), and the approve page lists them above the arguments, labelled as the application's record and not part of what the approver signs. The arguments are marked as model-written and unverified. The reasons come from the `gate-reason` record; no gate reads them, and the signed decision (`bide.approval.v3`) does not bind them. New: `agent.GateReason`, the `Why` fields of `agent.NotifyApproval` and `notify.Approval`, `approvals.Pending.Why`. The approve page bundle changes, so its `approve-page.SHA256SUMS` are new: an organisation that pins the bundle reviews the update.
- **`bide init -agent`.** Scaffolds an agent project instead of a plan flow: a tool that returns an email and declares it untrusted, a refund, and a taint policy (with `RequireProvenance`) whose escalation gate is two of three signed decisions that do not count the requester, so a side effect the model asks for after reading the email waits for a human decision. `-single-approver` makes the gate one unsigned decision for a team of one (weaker; the project's README says so). The project runs with no API key, checks its own story in `go test`, and writes `declarations.json` for `bide doctor -declarations`. The taint policy does not cover plan flows, so the plan-flow scaffold is unchanged.
- **`bide audit caps` (experimental).** Audits the amount-cap ledgers of a store, read-only: each ledger run must read under the ledger's own rules, its window total must be the sum of its live reserves, its slots must agree with the `cap-reserve` records of the runs that made the calls and with each attempt's `cap-intent`, and a release must be explained by the loop's `cap-release:` record or by the attempt's void. With `-sth` and `-pubkey` the ledgers and the runs' cap records must be what the newest signed heads commit to; with `-unanchored` the report says first that whoever can write the store can delete a slot or append a release undetected. `-namespace`, `-rule`, `-window` and `-run` narrow the audit and list what they left unchecked. `bide sample` now writes a small cap ledger (`bide audit caps -db sample.db -unanchored`). See the [amount caps guide](https://github.com/bide-ai/bide/blob/v0.24.0/docs/guides/amount-caps.md).
- **Cap release record.** When the loop releases a call's cumulative-cap reservation because the tool never began, it first journals why as a `cap-release:<attempt>` record in the run that made the call (`bide.cap-release.v1`). A write that fails releases nothing: the slot stays counted and the reconcile pass releases it after the void. The name is reserved.
- **Attempt markers carry `recorded_at`.** Every attempt marker the engine, `ClaimAttempt` or `ResolveHalt` claims now records the instant of the claim on the run's clock (`WithClock`, else the wall clock), readable as `Record.RecordedAt()`. `AttemptedAt` stays the wall clock, which the age of a halt is measured on. A caller cannot set it. `bide audit caps` dates a call's cap window by it.

Fixed:

- A model stream cut partway through an event (a dropped connection) now ends with the read error, retried as before, in every adapter that reads SSE (Anthropic, OpenAI, Gemini). Before, the half event was decoded first and the turn failed with a misleading "unexpected end of JSON input" in place of the failed read.
- Shipped in the patch releases v0.23.1 and v0.23.2 and in this release too: the cap reconcile pass reads the clock bound to its context instead of the wall clock, and `ClaimAttempt` stamps `AttemptedAt` from the wall clock (see Upgrading).

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.24.0

API changes:

- Added (experimental): `agent.WithTaintPolicy`, `agent.TaintPolicy` (with `RequireProvenance`), `agent.Trusted`, `ToolSpec.Trusted`, `agent.GateReason`, `(*Agent).Declarations`, the `Why` fields of `agent.NotifyApproval` and `notify.Approval`, `approvals.Pending.Why`. The generated [API reference](https://github.com/bide-ai/bide/blob/v0.24.0/docs/reference/api/index.md) lists every symbol.
- New commands and flags (experimental): `bide audit caps` and its flags, `bide doctor -declarations` and `-diff`, `bide init -agent` and `-single-approver`.

Upgrading:

- **Rolling out a taint policy.** A run is gated by the policy it started under. A run that started with no policy is never gated for its marks; a process without the policy refuses the side effects of a run that started under one, and a changed policy digest holds a call asked under the old one. An older binary ignores the policy and the new record members and runs a tainted run's calls ungated. Roll the whole fleet to v0.24.0 before enabling a policy.
- **`RequireProvenance`.** If you turn it on, every tool must declare `Untrusted` or `Trusted` and every new `Run`, `Send` or `SendOnce` must state its input's provenance, or you get `ErrConfig`. A sub-agent's run and a resume are not asked. A policy that does not set it is unchanged, and so is its digest.
- **Attempt markers.** Markers gain `recorded_at`; markers written before keep their form, and nothing that read them changes. `AttemptedAt` is on the wall clock, as in v0.23.2: under v0.23.1 `ClaimAttempt` stamped it from the context's clock, so if you ran v0.23.1 with a run clock that lagged the wall clock, a marker claimed in that time may look old to `ResolveHalt` with `WithMinHaltAge` and to the notifier's halt sweep.
- **`ClaimAttempt` claims bare attempt markers only** (shipped in v0.23.1). It returns `ErrConfig` and writes nothing for a name under a reserved prefix, the engine-derived `attempt:not-started:` and `attempt:retry:` forms, an empty name, a record whose kind is not `attempt`, a caller-set `AttemptedAt`, and an attempt record that carries a result, an approval, a model turn or a reconciliation. `cap-release:` is reserved now as well, and `Step` refuses it. Code that planted records through `ClaimAttempt` must stop; the engine's own paths are unchanged.
- **`bide init`** refuses (a usage error, nothing written) a module name with an empty element, an element that begins or ends with a dot or holds `..`, or text spelled like a marker of its project template. Its templates are filled in one pass.
- **Approve page.** The page bundle changed, so an organisation that pins `approve-page.SHA256SUMS` reviews and updates the pin. The signed decision is unchanged.
- Nothing else changes for flows and gates that declare no taint policy and no cap: they record what they did before.
