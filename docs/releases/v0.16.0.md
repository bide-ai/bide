**bide now tells a human when a run needs them, and signs when they decided.**

v0.16.0 adds a built-in notifier with a signed webhook, puts a signed decision time in every approval, gives `bide view` a new look, and makes a first run friendlier.

- **A built-in notifier.** `agent.WithNotifier` (and `plan.Builder.WithNotifier` for a flow) tells you, at least once and with a stable ID, when a run halts on an unknown outcome, waits for approval or is aborted, when recovery keeps failing, and when a notice itself is overdue. Delivery state lives in an audited trail, so a restart or a crash neither drops nor repeats a notice, and `agent.NotifyPending` sweeps up the runs of an application that has no `RecoverLoop`. The `notify` package ships the signed webhook: `notify.NewWebhook` posts a `bide.notification.v1` payload over HTTPS with an HMAC-SHA256 signature (secrets rotate with `WithSecrets`), a delivery ID bound to the payload, and optional mTLS; `notify.Verify` checks a request in one call. `notify.WithViewDB(path)` makes the `bide view` command in a notice one you can paste and run. TLA+ Model 14 checks the notify-once trail. [Get notified when a run needs a human](https://github.com/bide-ai/bide/blob/v0.16.0/docs/recipes/notify-human.md) is a complete program, and the [notifications guide](https://github.com/bide-ai/bide/blob/v0.16.0/docs/guides/notifications.md) covers the rest.

- **Signed decision times.** An approval decision now signs when the approver decided (`decided_at`, under `bide.approval.v3`), and the journal records when it was recorded (`recorded_at`). `bide audit verify-approvals` prints both with sanity flags, such as a decision dated after it was recorded, that never change the verdict. See Breaking below.

- **A premium viewer.** Every `bide view` page opens on a verdict (`VERIFIED`, `HALTED`, `WAITING FOR APPROVAL`), with the key numbers, a hand-drawn flow graph, an approver card for each approver, and a proof diagram that walks a record up to the signed root. It has a light and dark theme toggle, keyboard shortcuts (`?` lists them) and **Share this run**, which saves a PNG of the verdict.

  ![A verified run: the verdict, approver cards with their signed times, and the proof path to the signed root](https://raw.githubusercontent.com/bide-ai/bide/v0.16.0/docs/guides/img/run-viewer-agent-verified-dark.png)

  ![The image Share this run saves](https://raw.githubusercontent.com/bide-ai/bide/v0.16.0/docs/guides/img/run-viewer-share-dark.png)

- **A friendlier first run.** The `bide` command colors its output on a terminal. `bide doctor` checks what a first run depends on and says how to fix each problem. `bide sample` writes a sample journal of 14 runs and opens the viewer on it, with no code, no API key and no network. Errors a newcomer is likely to hit say what to do next. There are five complete [Recipes](https://github.com/bide-ai/bide/blob/v0.16.0/docs/recipes/index.md), a JSON Schema for flow configs (`plan/schema/flow.schema.json`) so editors complete and check a config as it is typed, and a new [Stripe refund example](https://github.com/bide-ai/bide/blob/v0.16.0/examples/stripe-refund/README.md): kill an agent mid-refund against Stripe's test mode API and watch it not refund twice.

  ![bide view on an agent run halted after a crash mid-refund](https://raw.githubusercontent.com/bide-ai/bide/v0.16.0/docs/guides/img/run-viewer-agent-halted-dark.png)

- **Durable event stores.** `store/sqlite` and `store/postgres` now keep a run's event trail in the same database as its journal: `(*Store).EventStore()` returns an `audit.EventStore`.

- **Fixes and housekeeping.** `RecoverLoop` and `MemWaker.Start` no longer run work after their context is cancelled. `bide demo -fast` exits when the demo is done, `bide audit` names a missing required flag in one line, and `bide doctor` only warns about an old Go where it can fetch 1.27 itself. Pull requests now add a changelog fragment under `changes/unreleased/` instead of editing the CHANGELOG, and the release step assembles them. Test coverage is reported to Codecov.

Try it with no setup:

    bide sample

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.16.0

API changes:

- Added: `agent.WithNotifier`, `agent.NotifyPending`, `agent.Notifier`, `plan.Builder.WithNotifier`, `plan.WithLoadedNotifier`, the `notify` package (`NewWebhook`, `Verify`, `Sign`, `WithSecrets`, `WithClientCert`), `(*Store).EventStore()` in `store/sqlite` and `store/postgres`, `Record.RecordedAt`, `agent.FormatTimestamp`, `audit.CheckDecisionTimes`, `agent.ApprovalRetallyStep` and `agent.PendingReapproval`.
- Changed: `agent.ApproveOption` is now an interface, and `agent.WithClock` is also an `ApproveOption`.
- New commands: `bide doctor` and `bide sample`.

Breaking:

- **`bide.approval.v3`.** `ApprovalDecisionBytes` takes `decidedAt`, `Decision.DecidedAt` is required (`SubmitDecision` refuses a zero one with `ErrConfig`), and decisions signed under `bide.approval.v2` no longer verify: they must be signed again. A run whose approval gate passed on v2 decisions before the upgrade, and whose call has not run, pauses for re-approval when it resumes (`agent.PendingReapproval`); a v2 denial stays final.
- **`run:aborted` is an object.** Its value is now `{"reason": ..., "aborted_at": ...}` instead of a JSON string. A `run:aborted` an earlier version wrote still loads and behaves the same, and `agent.Status` reads either form.

The [CHANGELOG](https://github.com/bide-ai/bide/blob/v0.16.0/CHANGELOG.md) has the details.
