**A gate can now run out of time, and `check -diff` catches more of the ways a flow change loosens a safeguard.**

v0.18.0 adds approval deadlines: a gate can have a timeout, an expired gate fails closed and never runs its call, and a decision written after the deadline never counts. The run viewer, `bide view -config`, `RenderMermaid` and `bide check -diff` show deadlines and `exclude_principal`. `bide check -diff` now flags a removed, loosened or no-longer-holding `assert` line and a node that is newly reachable without an approval gate, and a YAML flow file with more than one document is refused. Every release now signs each archive's SBOM and publishes a signed SBOM of the Go module set. The notifier and two result-before-bookkeeping races are fixed. Three building blocks for approver identity are in the tree but nothing uses them yet.

- **Approval deadlines.** `agent.ApprovalPolicy.Timeout` (in a flow config, `approval: {..., timeout: 48h}`) gives a gate a deadline, measured from the gate's recorded request and recorded once as `approval-deadline:<call>`, so a redeploy does not move it. A gate past its deadline with no terminal count records its expiry as its outcome, insert-once like a passing tally, so an expiry and a pass cannot both be recorded: whichever is recorded first stands. The call never runs (the model reads `agent.ExpiredResult`; a plan flow returns `plan.ErrApprovalExpired`), a decision recorded after the deadline never counts, and `agent.SubmitDecision`, `Approve`, the approvals endpoint and `bide approve` refuse one. A decision stamped on time whose write lands after the expiry does not count either, and every reader says so. The notifier sends `approval_expired` and closes the pending approval with the reason `expired`. Model 1b checks the expiry rules.

- **The viewer and the builder tools show deadlines and separation of duties.** `bide view` shows a waiting gate's deadline and the time left, an expired gate as `expired`, and a late decision as not counted; its Needs attention list puts gates with a deadline first, nearest first, flags one due within the hour, and marks one past its deadline `OVERDUE` with no approve command. `bide approve -list` shows the deadline too. `bide view -config`, `RenderMermaid` and `bide check -diff` show each gate's `timeout` and `exclude_principal` next to its need and approvers.

- **`bide check -diff` catches more weakenings.** Besides a gate's own policy, it now reports an `assert` line removed or loosened (a lower K, a larger N, or without `excluding the requester`) and a node that is newly reachable without passing a gate: any node that every path reached through an approval gate before and that some path now reaches without one is weakened, whatever its `safety`, whether through a new arm around a gate, a gate removed upstream, or a new node that uses a block only gated nodes used before. A `safety` moved toward read-only (side effect or unknown to idempotent or read-only, idempotent to read-only) is itself a weakening, and a node renamed together with a safety change is still judged on both. An `assert` line kept as written that no longer holds in the new config (violated, with the counterexample path, or undecidable) is a weakening too, so a new arm around a gate can no longer leave `every path to charge passes approval >= 2 of 3` false without a word, and so is a line that held and now holds only vacuously (no terminal, or no path to its node). A line written twice is one assertion, respelling a node name in quotes is no change, and a node renamed together with its assert line is a rename, not a removed assertion. `-fail-on-weaken` exits 1 on these. Removing or lengthening a `timeout`, or dropping `exclude_principal`, is a weakened gate; adding either is a strengthened one. A node renamed with the same block, safety and edges is reported as renamed, not as a removal and an addition.

- **A YAML flow file with more than one document is refused.** `bide check`, `bide view -config` and the YAML flow of a `bide init` project now fail with `more than one YAML document`, where the first document was read and the rest silently ignored, so a second flow or policy in the same file was read by no check and no loader.

- **Signed SBOMs, and an SBOM of the module set.** Each archive's SPDX SBOM has its own keyless cosign signature, and `bide_X.Y.Z_modules.sbom.json` (with its `.sigstore.json`) is the SBOM of the published Go module set: what an application gets with `go get`, resolved only through the public Go proxy and checked to list every published bide module at the release's version. The release workflow verifies each signature, and [Verify a release](https://github.com/bide-ai/bide/blob/v0.18.0/docs/trust/verify-releases.md) shows how to verify and use them.

- **Notifier and bookkeeping fixes.** A notification call that had returned could still be counted as in flight, so an immediate retry in the same round was refused as an abandoned call and the attempt was lost; the engine now records that a call is over before it answers. `audit.AuditedEventStore` and `agent.RecoverLoop` no longer hand a result to a caller before releasing their own slot, and a repository check (`internal/tools/sendcheck`) fails the build when a goroutine does. `agent.Notifier` is now documented as called from several goroutines at once, so a custom Notifier must be safe for concurrent use. Flushing the notifier from inside the `WithNotifyErrors` handler now returns an error instead of deadlocking.

- **Building blocks for approver identity, not yet used by approval gates.** `audit/rfc3161` is a strict verifier for RFC 3161 time-stamp tokens, and `audit.IdentityPolicy` with `CertIdentity.VerifyChain` verifies a certificate chain for an approver identity, and `audit.StatusSnapshot` with `CertIdentity.EvaluateStatus` reads CRLs and reports whether a certificate in that chain was revoked when the decision was made (delta CRLs are refused for now). None of these is called by any command or gate: approval gates do not read certificates, CRLs or time-stamp tokens, and no behaviour changes. Binding approvers to certificates comes in a later release.

- **A generated SDK API reference with stability labels.** `docs/reference/api/` lists every exported constant, variable, function and type of every package in the published modules, each with its declaration, the first sentence of its doc comment, a pkg.go.dev link and a label: core, experimental, or building block (not yet used by approval gates, the label of `audit/rfc3161` and the certificate verification core in `audit`). It is generated from the Go sources by `internal/tools/apiref`, and CI fails when a page is stale, an exported symbol has no doc comment, or a package has no label; [Stability](https://github.com/bide-ai/bide/blob/v0.18.0/docs/trust/stability.md) has the package table.

- **Documentation.** A retention and archiving guide (`docs/guides/retention.md`), runnable `examples/intake` and `examples/notify-routing`, translated READMEs and tours that match the English ones, and a link check in CI.

API changes:

- Added: `agent.ApprovalPolicy.Timeout`, `agent.ApprovalDeadline`, `RecordedDeadline`, `ExpiredResult`, `ErrApprovalExpired`, `ReasonLate`, `ReasonAfterExpiry`, `ApprovalTally.Expired` and `ExpiresAt`, `EvaluateGate`'s `Expired` and `Deadline`; `plan.ErrApprovalExpired`, `plan.TopologyGate.TimeoutText`, `planview.CompareAssertions`, `ConfigReport.UngatedPath` and a `weakening` field on `DiffView` and each `Change`; `runview.Gate` fields `ExpiresAt`, `Timeout`, `Expired`, `Overdue` and `Due`; package `audit/rfc3161`; `audit.IdentityPolicy`, `audit.CertIdentity.VerifyChain`, `audit.CertError`, `audit.StatusSnapshot`, `CertIdentity.EvaluateStatus` and `agent.ReasonNoCert`, `ReasonCertChain`, `ReasonCertIdentity`, `ReasonCertUsage`, `ReasonCertWindow`, `ReasonRevoked`, `ReasonStatusUnknown`, `ReasonStatusStale`; `plan.AssertionResult.Vacuous`, `plan.RenameAssertion`, and `safety` as a value of `Change.Weakening`.

Behaviour changes:

- **A gate with a `Timeout` can expire.** A run that waits past the deadline records the expiry when it is next driven and its call never runs.
- **`bide check -diff` and `-fail-on-weaken` report more.** Any node that every path reached through an approval gate before and that some path now reaches without one is a weakening, whatever its `safety`, and a `safety` moved toward read-only is a weakening on its own. A removed, loosened or no-longer-holding `assert` line, and a Switch arm condition changed beside an arm that leads to an ungated effect, are reported too. Under the broad rule `-fail-on-weaken` can fail on a read-only node wired in around a gate, and on an assertion whose target became unreachable, which now holds only vacuously.
- **A multi-document YAML flow file is now an error.** Programs that convert YAML themselves should decode with a `yaml.Decoder` and require the next decode to return `io.EOF`.
- **A custom `agent.Notifier` must be safe for concurrent use.** The engine has always called it from several goroutines; check yours for an unguarded counter, map or buffer.
- **Webhook receivers** see a new kind of event, `approval_expired`; one that treats every POST as a new alert should filter on `kind`.

Upgrading:

- Finish or resolve runs before upgrading, as with every pre-release.
- Run `bide check <new> -diff <old> -check -fail-on-weaken` over your flow configs once: it can now report weakenings it did not before.
