**Taint in plan flows: a flow that reads untrusted content needs a second look before it acts.**

v0.26.0 brings the taint policy to plan flows. Once a run has read content a node declared untrusted, each later node that can have a side effect waits for an escalation gate, or is refused. The taint follows the run through nested flows and agents, the second look can be required from other people, and `bide check` and the editor show before anything runs which nodes can read untrusted data. The new Go names and flags are experimental: they may change in a minor release.

<!-- docsnip: setup ctx context.Context; journal *agent.Journal; fetchEmail func(context.Context, string) (string, error); issuePayment func(context.Context, string) (string, error); returns error -->
```go
f := plan.New[string, string]("refund")
fetch := f.Step("fetch", fetchEmail, plan.Untrusted("inbound-email"))
pay := f.Step("pay", issuePayment)
f.Edge(fetch, pay)
f.WithTaintPolicy(agent.TaintPolicy{Gate: agent.SingleApproval()})
flow, err := f.Build()
if err != nil {
	return err
}
_, err = flow.Run(ctx, journal, "run-1", "msg-42")
// err is an *agent.ApprovalPending for node:pay:taint; pay has not run
```

The payment waits for a human decision on `node:pay:taint` because the run has read an inbound email. Approving it clears nothing: the next side-effecting node is asked again.

Tainting bounds the consequences of a request a model was steered into. It does not detect or prevent prompt injection; an approver can still be persuaded by an injected justification. The [known limitations](https://github.com/bide-ai/bide/blob/v0.26.0/docs/KNOWN-LIMITATIONS.md#untrusted-content-and-the-taint-policy) list what the policy leaves out, and the [untrusted content guide](https://github.com/bide-ai/bide/blob/v0.26.0/docs/guides/untrusted-content.md#plan-flows) has the rules for flows.

- **Flow taint enforcement (experimental, Go only).** Give a flow an `agent.TaintPolicy` and declare what each node's results carry. After untrusted content is read, a node that can have a side effect needs the policy's gate first, or is refused under `Refuse`. `Flow.Conform` checks from the journal that every node that ran met its obligation, and a flow that declares taint loads and passes `bide check`.
- **Run input provenance.** `Flow.Run` accepts `agent.WithUntrustedInput` and `agent.WithTrustedInput`, so a run whose input came from outside starts tainted.
- **Taint crosses nested flows and agents.** A flow or agent started by a tainted node inherits the taint, and what it reads comes back up to the node that started it. A flow run as an agent's tool marks the tool result when it ended with a mark, so the agent's next turn is tainted.
- **Separate approvers (experimental).** `SeparateApprovers` makes the escalation a second look by other people: those who approved the call's own gate do not count on the escalation, and an escalation left with too few approvers is denied instead of waiting. The approvals intake, `bide approve`, the run viewer and the notifier stop presenting an excluded approver as eligible, and `bide audit verify-approvals -separate-approvers` recounts it offline.
- **The static view.** `bide check` prints a taint section: the nodes that may read a declared source, and what the policy would do to each. `bide check -diff` reports a side-effecting node that newly reads a source and flags it as `UNTRUSTED EXPOSURE WIDENED` when no policy covers it. A diff whose taint cannot be compared on one side is labelled not certified, and `-fail-on-weaken` fails on it; a diff with no `-blocks` on either side prints "taint not compared (no -blocks)" and its certification is unchanged.
- **The editor shows it too.** `bide edit` marks each node, explains the path from a source in the inspector, and shows the `UNTRUSTED EXPOSURE WIDENED` banner when an edit newly exposes a side-effecting node.
- **Flow declarations in `bide doctor`.** `bide doctor -declarations` and `-diff` read a flow's taint declarations and report a removed source, a new exemption, a lower gate or `require_provenance` turned off as weakened.

API changes:

- Added (experimental): `Builder.WithTaintPolicy`, `plan.WithLoadedTaintPolicy`, the node options `plan.Untrusted`, `plan.Trusted` and `plan.TaintExempt`, `plan.ErrTaintRefused`, `agent.TaintPolicy.SeparateApprovers`, `agent.ApprovalPolicy.SeparatedFrom`, `agent.ApprovalTally.ExcludedBySibling`, `agent.ReasonSibling`, `agent.ReasonNoSibling`, `plan.TaintPolicyDescription` and `plan.DescribeTaintPolicy` (with the matching fields of `plan.RegistryDescription` and its block descriptions), `plan.ConfigReport.Taint` (`plan.NodeTaint`), `plan.InspectTaintPolicy`, `flowedit.WithTaintPolicy`. `Flow.Run` now takes `agent.WithUntrustedInput` and `agent.WithTrustedInput`. The generated [API reference](https://github.com/bide-ai/bide/blob/v0.26.0/docs/reference/api/index.md) lists every symbol.
- New flags (experimental): `bide audit verify-approvals -separate-approvers`.
- New records: the `taint-mark:` and `taint-child:` records that carry marks between a nested flow and the node that started it, the `subflow:<tool>` mark on the result of a flow run as an agent's tool, and the escalation instance `node:<name>:taint`.
- New record members: the tally's `excluded_by_sibling`, the gate-reason record's `separate_approvers`, the `taint_declarations` and `taint_sources` members of a flow's `run:start`, and in `plan.RegistryDescription` version 2 the block members `untrusted`, `trusted` and `taint_exempt` and the description members `taint_declared` and `taint_policy`. `taint_declarations` is written for a flow with a taint policy and `taint_sources` for a flow with no policy that declares a source; a flow that declares nothing writes neither, and `excluded_by_sibling` and `separate_approvers` appear only when set.
- Changed: `Step`, `Parallel` and `ResolveHalt` refuse a step name that starts with `taint-mark:` or `taint-child:` (`agent.IsReservedStepName` reports them), and a live model turn whose tool-use ID starts with `node:` fails with `ErrToolUseIDInvalid`; a journal that already holds such an ID still replays and resumes.
- Changed: `plan.DescriptionVersion` is 2, and `Describe` writes it.
- Compatibility: a run that started under a flow taint policy cannot be driven by v0.25.x or earlier, which do not read its taint records. A description written by v0.26.0 is version 2, which v0.25.x refuses; v0.26.0 reads version 1 and 2. A flow with no policy and no declared source records and behaves as before.

The [CHANGELOG](https://github.com/bide-ai/bide/blob/v0.26.0/CHANGELOG.md) has the details.
