**Taint in plan flows: a flow that reads untrusted content now needs a second look before it acts.**

v0.26.0 brings the taint policy to plan flows. A flow run that has read untrusted content needs the policy's escalation gate (or is refused) before each node that can have a side effect; the taint follows the run through nested flows and agents, in both directions; the escalation can be made a second person's; and `bide check` and the editor show, before anything runs, which nodes can read untrusted data. The new Go names and flags are experimental: they may change in a minor release.

Tainting bounds the consequences of a request a model was steered into. It does not detect or prevent prompt injection; an approver can still be persuaded by an injected justification. The [known limitations](https://github.com/bide-ai/bide/blob/v0.26.0/docs/KNOWN-LIMITATIONS.md#untrusted-content-and-the-taint-policy) list what the policy leaves out, and the [untrusted content guide](https://github.com/bide-ai/bide/blob/v0.26.0/docs/guides/untrusted-content.md#plan-flows) has the rules for flows.

- **Flow taint enforcement (experimental, Go only).** `Builder.WithTaintPolicy` (or `plan.WithLoadedTaintPolicy` for a loaded flow) gives a flow an `agent.TaintPolicy`. `plan.Untrusted`, `plan.Trusted`, `plan.TaintExempt`, a tool's own declarations and the `untrusted` key of a config node say what each node's results carry. Once a run has read untrusted content (a node that declares a source, the run's input when `WithUntrustedInput` names it, or what a flow a node started brought up), a node that can have a side effect needs the policy's escalation gate on its own subject, `node:<name>:taint`, before its attempt claim, or is refused under `Refuse` (`plan.ErrTaintRefused`). The run records its declarations in `run:start`, and `Flow.Conform` checks from the journal that every node that ran met its obligation. `Build`, `Load`, `Validate` and `bide check` accept a flow that declares taint.
- **Run input provenance.** `Flow.Run` takes `agent.WithUntrustedInput` and `agent.WithTrustedInput`. The source is recorded in `run:start`, and an untrusted source is the first mark of a run under a flow taint policy.
- **Taint crosses nested flows and agents.** A flow a node's body starts inside a tainted run inherits the status and marks, as an agent child does, and sends the marks it learned back up to that node (`taint-mark:` and `taint-child:` records), also when `ResolveHalt` records the node's result. An agent a node's body runs hands up the marks it read before the node is recorded. A flow run as an agent's tool marks the tool result `subflow:<tool>` when it ended with a mark, so the agent's next turn is tainted.
- **Separate approvers (experimental).** `agent.TaintPolicy.SeparateApprovers` makes the escalation gate a second look by other people: on a call's escalation instance (`<call>#taint`, or `node:<name>:taint` in a flow) the approvers whose decisions the call's own gate counted do not count, and an instance left with too few approvers is denied instead of waiting. `agent.New` and `plan` `Build` refuse a configuration that cannot meet it. The approvals intake, `bide approve`, `bide approve -list`, the run viewer and the notifier stop presenting an excluded approver as eligible, and `bide audit verify-approvals -separate-approvers` recounts an instance with the same exclusion.
- **The static view.** `bide check` prints a taint section: the nodes that may read a declared source, and what the policy would do to each (`escalates`, `refused`, `exempt`, or `reads untrusted` when no policy is given). `bide check -diff` reports a side-effecting node that newly reads a source, and flags it as `UNTRUSTED EXPOSURE WIDENED` when the policy is known to be absent. A diff whose taint cannot be compared on one side (the policy is not given, or only one side has `-blocks` and it states a source) is labelled not certified, and `-fail-on-weaken` fails on it; a diff with no `-blocks` on either side prints "taint not compared (no -blocks)" and its certification is unchanged. `plan.ConfigReport.Taint` and `plan.InspectTaintPolicy` give the same view to a program, and `plan.InspectConfigDescribed` reads the description's policy.
- **The editor shows it too.** `bide edit` marks each node with words and a ring, adds a Taint section to the inspector with the path from a source, a Taint panel, an announcement when the view changes, and the same `UNTRUSTED EXPOSURE WIDENED` banner when an edit newly exposes a side-effecting node. `flowedit.WithTaintPolicy` gives an embedded editor the flow's policy; `bide edit -blocks` uses the description's.
- **Flow declarations in `bide doctor`.** `plan.RegistryDescription` is version 2: each block carries `untrusted`, `trusted` and `taint_exempt`, and the description carries the flow's policy (`plan.DescribeTaintPolicy`). `bide doctor -declarations` and `-diff` read it, and report a removed `Untrusted` source, a new `TaintExempt`, a lower gate or `require_provenance` turned off as weakened. A version 1 description is still read.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.26.0

API changes:

- Added (experimental): `Builder.WithTaintPolicy`, `plan.WithLoadedTaintPolicy`, the node options `plan.Untrusted`, `plan.Trusted` and `plan.TaintExempt`, `plan.ErrTaintRefused`, `agent.TaintPolicy.SeparateApprovers`, `agent.ApprovalPolicy.SeparatedFrom`, `agent.ApprovalTally.ExcludedBySibling`, `agent.ReasonSibling`, `agent.ReasonNoSibling`, `plan.TaintPolicyDescription` and `plan.DescribeTaintPolicy` (with the matching fields of `plan.RegistryDescription` and its block descriptions), `plan.ConfigReport.Taint` (`plan.NodeTaint`), `plan.InspectTaintPolicy`, `flowedit.WithTaintPolicy`. `Flow.Run` now takes `agent.WithUntrustedInput` and `agent.WithTrustedInput`. The generated [API reference](https://github.com/bide-ai/bide/blob/v0.26.0/docs/reference/api/index.md) lists every symbol.
- New flags (experimental): `bide audit verify-approvals -separate-approvers`.
- New record members: the tally's `excluded_by_sibling`, the gate-reason record's `separate_approvers`, the `taint_declarations` and `taint_sources` members of a flow's `run:start`, and in `plan.RegistryDescription` version 2 the block members `untrusted`, `trusted` and `taint_exempt` and the description members `taint_declared` and `taint_policy`. `taint_declarations` is written for a flow with a taint policy and `taint_sources` for a flow with no policy that declares a source; a flow that declares nothing writes neither, and `excluded_by_sibling` and `separate_approvers` appear only when set.
- Changed: `Step`, `Parallel` and `ResolveHalt` refuse a step name that starts with `taint-mark:` or `taint-child:` (`agent.IsReservedStepName` reports them), and a live model turn whose tool-use ID starts with `node:` fails with `ErrToolUseIDInvalid`; a journal that already holds such an ID still replays and resumes.
- Changed: `plan.DescriptionVersion` is 2, and `Describe` writes it.
- Compatibility: a run that started under a flow taint policy cannot be driven by v0.25.x or earlier, which do not read its taint records. A description written by v0.26.0 is version 2, which v0.25.x refuses; v0.26.0 reads version 1 and 2. A flow with no policy and no declared source records and behaves as before.

The [CHANGELOG](https://github.com/bide-ai/bide/blob/v0.26.0/CHANGELOG.md) has the details.
