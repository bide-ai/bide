**Compare a flow with a run in the editor, and refuse a wrapper that claims a safer tool than the one it wraps.**

v0.25.0 finishes the fourth phase of the flow editor: `bide edit` can compare the file you are editing with the topology a run journaled, draw the run's path on the flow, and list the unfinished runs a change would refuse. It also closes a gap in the wrapper checks: a tool wrapper can no longer declare a `Safety` safer than a tool inside it without saying why. The new Go names (`agent.RaisesSafety`, `ToolSpec.RaisesSafety`, `plan.InspectTopology`) and the new `bide edit` flags are experimental: they may change in a minor release.

- **Compare with a run (experimental).** `bide edit -run <id>` with a store (`-db`, `-postgres`, `-postgres-env` or `-journal`, the flags `bide view` takes, opened read-only) adds a panel, **Compared with a run**. It says SAME DIGEST (typed mode), NO DIFFERENCE SEEN (structural mode, where kinds, types and gates are not compared), DIFFERS FROM THE RUN with the changes the topology digest covers, or CANNOT COMPARE, and that a run paused under a different topology will not resume under the file. It compares topologies and nothing more: it does not say the run followed the file, and safety and assert lines, which are not in a journal or the digest, are not compared. It never blocks a save. See [Compare with a run](https://github.com/bide-ai/bide/blob/v0.25.0/docs/guides/flow-editor.md#compare-with-a-run).
- **The run's path on the canvas.** The page draws what the run did on the flow (a ring and words per node: ran, started with no result recorded, paused at its approval gate; a dashed line over each connection taken), laid on the file by name with the session's renames, and lists what the file cannot show. The run is read once and again on **Reload run**.
- **Unfinished runs this file would refuse.** With a store, with or without `-run`, a second panel lists the store's unfinished runs by the digest each recorded (at most 5000 runs, said as "at least") and says which a drive under the file (resume, recovery or restart) would refuse. Runs of another flow and runs that recorded no digest yet are counted apart.
- **`plan.InspectTopology`.** `plan.InspectTopology(t Topology) ConfigReport` is the report of a declared `Topology` alone (its digest, its approval gates, which nodes every path to passes through a gate), computed by the code `InspectConfig` uses. It is for a tool that holds a topology and no config, such as the one a run journaled (`JournaledTopology`). It does not validate and never panics.
- **A wrapper may not claim a safer tool (experimental).** `agent.New` refuses with `ErrConfig` a wrapper whose declared `Safety` is safer than a tool it embeds or unwraps, at any depth (the order is a side effect, then `Idempotent`, then `ReadOnly`), because the agent acts on the wrapper's `Safety`: a `ReadOnly` wrapper over a side-effecting tool escaped the taint gate and was re-run on resume. A wrapper that really does make the call safer declares `agent.RaisesSafety(reason)` (or `ToolSpec.RaisesSafety`); the reason is in the declarations document and, only when set, in its digest, so existing digests are unchanged. `bide doctor -declarations` lists it, and `bide doctor -diff` reports adding it as WEAKENED and removing it as strengthened. `bide doctor -diff` also reports any tool that becomes safer to re-run as WEAKENED.
- **Amount caps are labelled experimental.** `agent.WithCaps`, `agent.WithCapNamespace` and `ToolSpec.Caps` are marked experimental in their documentation and the API reference, and [stability](https://github.com/bide-ai/bide/blob/v0.25.0/docs/trust/stability.md) lists every experimental name and command of v0.23.0 to v0.25.0. No behavior changes: a configured cap still refuses the call it covers.

Fixed:

- `bide audit verify-evidence` and `bide audit verify-decision-coverage` name a step whose key holds a call ID by that ID (`step "approval-pending" of call "c2#taint"`), not by the escaped form the engine stores. Display only.
- `bide view` says why a gate's signatures were not checked when the `-sth` or `-evidence` given is for another run, and names the run the proof is for, instead of asking for flags the user had already passed.
- The core module and its test code build on Solaris and illumos again (`go vet ./...` was failing in the core, `flowedit` and `cmd/bide-anchor`). `notify/relay`'s state-file lock builds everywhere; on a platform with no file lock (Solaris, AIX) a relay refuses a `StatePath` at start, as before on any such platform.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.25.0

API changes:

- Added (experimental): `agent.RaisesSafety`, `ToolSpec.RaisesSafety`, `plan.InspectTopology`. The generated [API reference](https://github.com/bide-ai/bide/blob/v0.25.0/docs/reference/api/index.md) lists every symbol.
- New flags (experimental): `bide edit -run`, and the store flags `-db`, `-postgres`, `-postgres-env` and `-journal` on `bide edit`. See the [command reference](https://github.com/bide-ai/bide/blob/v0.25.0/docs/reference/cli.md).

Upgrading:

- **Wrappers.** An agent with a wrapper that declares a safer `Safety` than a tool inside it (for example a `ReadOnly` wrapper over a side-effecting tool) now fails at `agent.New` with `ErrConfig`, naming the wrapper, the tool and both levels. Declare the inner tool's `Safety`, or `agent.RaisesSafety(reason)` if the wrapper really makes the call safer. The wrapper check on an `Unwrap` chain now also looks inside the tools each chain tool embeds, for every property it checks (approval gate, `Timeout`, `Caps`, `Untrusted` and `Safety`), so a wrapper that reaches a gated, capped, untrusted or less safe tool through `Unwrap` and was accepted before can now fail at `New` until it declares the same.
- **Declarations.** The format stays `bide.declarations.v1`, and every document the agent now dumps carries a `tracks_idempotent` member (and, where they apply, `idempotent` and `raises_safety`), so an older `bide doctor` (v0.24.0 and earlier) refuses a new document as having an unknown member. In the other direction, `bide doctor -diff` of a baseline dumped by an older version against a new dump with an `Idempotent` side-effecting tool reports one WEAKENED line asking you to regenerate the baseline with the new version: a pipeline regenerates its baseline once after upgrading.
- Nothing else changes for flows and agents that use no wrapper that claims a safer level: they record what they did before.
