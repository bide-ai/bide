**One command, from first run to proof.**

v0.14.0 puts bide's tools behind a single `bide` command and adds a project scaffold, so a new user can see the guarantee, build on it, inspect a run and verify it, in that order.

- **See it.** `bide demo` runs a payment agent, kills its process mid-charge, and shows the restart halting instead of charging again. The run is then resolved and opened in the viewer with its approvals and audit proof verified. No API key needed.
- **Build on it.** `bide init my-agent` scaffolds a working project: a plan flow with a 2-of-3 approval gate in front of a refund, a SQLite journal, recovery of interrupted runs at startup, and a marked block for switching to a real model.
- **Inspect it.** `bide view` shows a run from its journal. `bide check flow.yaml` draws a flow definition and marks its problems before it runs; `-check` and `-strict` make it a CI step.
- **Prove it.** `bide audit` is the offline verifier, unchanged in behavior.

Also new:

- **Approval gates on plan flow nodes.** A gated node pauses until k of n signed decisions are recorded for that node and input, per loop iteration, using the same journaled approval machinery as agent tool calls. Modelled in TLA+, including across crashes and two drivers.
- **Flow runs journal their declared topology**, so `bide view` draws any flow run from its journal, digest verified.
- **The core module requires only the Go standard library**, checked in CI by an allowlist.
- **Reproducible release binaries.** `scripts/repro.sh` rebuilds a release from its tag and compares the bytes.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.14.0

API changes:

- One command, `bide`, replaces `bide-audit`, `bide-view` and `bide-demo` (`bide audit`, `bide view`, `bide demo`; flags are unchanged). `cmd/bide-view` is a deprecated signpost; the Homebrew `bide-audit` formula is renamed to `bide`.
- Approver IDs must be printable ASCII (0x21 to 0x7E); others are refused with `ErrConfig`.
- Plan flows accept approval gates (`plan.Approval`, or `approval:` in a flow config). `approval-request:` is a new reserved step prefix, and a flow run journals a `flow:topology` record.
- New: `plan.TopologyDigest`, `plan.JournaledTopology`, `plan.InspectConfig`, the `plan/planview` package, and `plan.ErrApprovalDenied`.
