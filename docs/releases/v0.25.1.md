**Refuse inputs that were silently misread, and stop tagging the bide-view stub.**

v0.25.1 is a patch release. It makes three commands and the flow loader refuse an input they used to accept and misread, and it removes the `cmd/bide-view` stub module. No journal, proof or API format changes.

- **Two exports of one run are refused.** `bide view`, `bide edit`, `bide audit verify-receipts`, `bide audit redactions` and `bide audit notifications` used to let the later `-journal` file on the command line silently replace an earlier export of the same run, so a stale or substituted export could be shown as that run, and a verdict could change with the order of the flags (a redacted journal and the whole journal it came from gave PASS or FAIL depending on which was listed last). They now refuse two exports of one run and name both files and the run ID: a usage error (exit 2) for `bide view` and `bide edit`, an unusable input (exit 4) for the audit commands. Pass one export per run; exports of different runs are unchanged.
- **`safety` and `approval` on a wiring element are refused.** A flow config that sets `safety` or `approval` on an `edge` or `switch` wiring element is now refused with `ErrConfig` naming `wiring[i]`, by `Load`, `Validate` and `InspectConfig`. The key has no node to apply to there and was accepted and dropped, so a config could look gated and not be.
- **`bide migrate -h` names everything the migration creates**, including the `bide_holds` table, the `bide_redact_v3` function and the `EXECUTE` revokes on older redaction functions. Help text only; the migration is unchanged.
- **`cmd/bide-view` is removed.** The module was a stub that printed that `bide-view` is now `bide view`. Its last tag is `cmd/bide-view/v0.25.0`, and `go install github.com/bide-ai/bide/cmd/bide-view@latest` still resolves to that stub; install `cmd/bide` and run `bide view`. A release now tags 19 nested modules, one fewer.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.25.1

Upgrading:

- **Flow configs.** A config that sets `safety` or `approval` on an `edge` or `switch` wiring element used to load, with the key dropped. It now fails to load with `ErrConfig`. Remove the key, or set it on the node it was meant for. The change can only make a config stricter: nothing that loaded before is read differently.
- **Scripts that pass two `-journal` exports of one run** to `bide view`, `bide edit` or the three audit commands now exit 2 or 4. Pass one export per run.
- **Nothing else changes.** No Go API is added or changed, and journals, proofs and signed formats are as in v0.25.0.

The [CHANGELOG](https://github.com/bide-ai/bide/blob/v0.25.1/CHANGELOG.md) has the details.
