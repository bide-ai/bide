**See every run, watch one live, and check a flow's policy before it ships.**

v0.15.0 grows `bide view` and `bide check` from a page for one run into a viewer for the whole journal and a policy check for flow configs. Everything stays read-only, loopback-only and local.

- **A run list.** `bide view -db run.db` with no `-run` opens on every run in the journal: its ID, kind, state (completed, halted, waiting for approval, in progress, aborted, cancelled), when it started, and its record count, newest first. Filter by state, kind or run ID; the same list is served as JSON at `/runs.json`. A run's `run:start` now records when it started (`RunStart.StartedAt`).

  ![The run list](../guides/img/run-viewer-run-list-dark.png)

- **Live mode.** Open a run that is still in progress, from a SQLite or Postgres journal, and the page follows it: timeline rows appear as records land, and the end state, approval gates and flow graph update in place until the run ends. No flag needed.

  ![A run followed live](../guides/img/run-viewer-live-dark.gif)

- **A risk map.** `bide view -config flow.yaml` colors each node by what a crash does to it: a side effect halts and asks, a read-only or idempotent node re-runs. It marks approval gates and sums up how many side effects sit behind a gate.

  ![The risk map](../guides/img/run-viewer-config-risk-dark.png)

- **Policy assertions.** A flow config's new `assert:` list states policy about the graph, such as `every path to charge passes approval >= 2 of 3` or `no side effect after charge`. Each is decided over the declared graph, loops included. A violated assertion is an error with the shortest counterexample path, drawn in red on the `bide view -config` page and printed by `bide check`, which exits 1, so it works as a CI gate.

  ![A violated assertion with its counterexample path](../guides/img/run-viewer-config-assert-dark.png)

- **Flow diffs.** `bide check flow.yaml -diff <old>` compares a config with an earlier version, from a file or a git revision (`main:flow.yaml`). Added nodes and edges are green, removed ones dashed red, changed ones amber, and a weakened or removed approval gate is called out first. With `-check` it prints the changes for CI, and `-fail-on-weaken` exits 1 when a gate was weakened.

  ![A strengthened approval gate](../guides/img/flow-diff-strengthened-dark.png)
  ![A weakened approval gate, called out first](../guides/img/flow-diff-weakened-dark.png)

Try them on the samples in `examples/plan/flows`: `refund-policy.yaml` and `refund-policy-bypass.yaml` for assertions, and `refund-v1.yaml` and `refund-v2.yaml` for a diff.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.15.0

API changes (all additions):

- `agent.RunStart.StartedAt` (`started_at`), recorded by a run's first drive. Runs journaled by earlier versions show no start time.
- A flow config's `assert` list (ignored by `plan.Load`); `plan.InspectConfig` reports it in `ConfigReport.Safety`, `.Gated` and `.Assertions` (`plan.NodeSafety`, `plan.AssertionResult`).
- `plan/planview`: `DiffHandler` and `CheckDiff`.
- `bide check` accepts flags after the file names.

The CHANGELOG has the details.
