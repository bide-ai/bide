**Edit a flow's structure and its blocks' types in the browser, and make the pages look the way your institution needs.**

v0.22.0 turns `bide edit` from an editor of one node's gate and safety into an editor of the whole flow, teaches it what your program's blocks accept, and gives every visual page checked themes. Everything the editor writes is still a verified splice of your config text, and a change that weakens an approval policy is still called out first.

- **Structure editing.** `bide edit` adds, removes, renames and reorders nodes; wires edges, switches, arms, `else`, joins and loop bounds; and connects two nodes by dragging (a mouse, a pen or a finger; every connection can also be made from the keyboard). Undo and redo cover every one of these edits. A rename reads as a weakening of a gated node, and a removal first lists what else goes. See the [flow editor guide](https://github.com/bide-ai/bide/blob/v0.22.0/docs/guides/flow-editor.md).

  ![bide edit with a drag to connect in progress: a dotted line from the charge node's port to notify, the green ALL ASSERTIONS HOLD banner, the outline and the inspector with charge's 2-of-3 approval gate](https://raw.githubusercontent.com/bide-ai/bide/v0.22.0/docs/guides/img/flow-edit-structure.png)

- **Typed editing.** `bide edit -blocks <file>`, `flowedit.WithRegistry` and `flowedit.WithBlocks` check the flow against your blocks: a palette of registered blocks with their types, connections refused when the types do not fit, the approval gates your blocks declare in Go counted in the weakened banner, and the flow's digest. The same description (`Registry.Describe`) lets `bide check -blocks` and `bide view -config -blocks` run these checks in CI without your Go code, and the result says it was checked against the file, not the program.

  ![bide edit's Blocks palette: each registered block with the types it takes and gives, its safety and its approval gate, and whether the flow uses it](https://raw.githubusercontent.com/bide-ai/bide/v0.22.0/docs/guides/img/flow-edit-typed-blocks.png)

- **Themes.** `bide view`, `bide edit` and the approve page draw from checked themes: light, dark and high-contrast, with `prefers-contrast` and forced colours honoured, and no state told apart by colour alone. A theme of your own is a small JSON file (`-theme file.json`) that `bide theme check` measures for contrast, colour-blind separation and the meaning of its colours before a page serves it. A Go program chooses themes through the public `theme` package and `planview.WithThemes`, `WithDefaultTheme` and `WithThemeLock` (the same three on `flowedit`). See the [themes guide](https://github.com/bide-ai/bide/blob/v0.22.0/docs/guides/themes.md).

  ![bide view's flow config page in the high-contrast theme](https://raw.githubusercontent.com/bide-ai/bide/v0.22.0/docs/guides/img/themes-high-contrast.png)

- **Structured problem kinds.** `plan.InspectConfig` and `InspectConfigDescribed` return `Findings` beside `Problems`: each error carries a stable `Kind`, the full names it concerns, and the types or levels that differ, so a Go program can act on a problem without reading its message. `Load` and `Validate` now list every problem, not the first.
- **A stricter, more complete check.** `bide check` and `bide view -config` make every wiring check `plan.Load` makes, so a config they pass loads. The anchors grew with it: `bide-anchor` reads Google Cloud Storage (`-backend gcs`) as well as S3, and checks an S3 bucket's versioning, Object Lock and encryption.

Security:

- The strict JSON reader refuses documents nested more than 128 levels deep (10,000 for payloads a journal keeps verbatim), closing a memory and CPU exhaustion path present since v0.8.0.

Fixed:

- `planview.CheckDiff` and `DiffHandler` passed a diff silently when a side had errors against its Registry (since v0.15.0); such a diff is now checked structurally and marked not certified.
- `plan.InspectConfig` with a Registry wrongly reported "Model step has no bound model" for a Model block (since v0.14.0).
- A named pipe or device given where bide expects a file no longer hangs it.
- A gate set in both a block and the config is one problem that says how to fix it.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.22.0

API changes:

- Added: the `theme` package (public, 0.x); `planview.WithThemes`, `WithDefaultTheme`, `WithThemeLock` and the same three on `flowedit`; `plan.Registry.Describe` and `RegistryDescription`; `plan.InspectConfigDescribed`; `plan.AllowUnusedBlocks`; `plan.ConfigReport.Findings`, `plan.Finding` and the `Problem*` kinds; `flowedit.WithRegistry`, `WithBlocks` and the structure operations; `bide edit -blocks -theme -theme-default`; `bide check -blocks -old-blocks`; `bide view -theme -theme-default`; `bide theme check`; `bide-anchor -backend gcs -project -kms-key -retention -lock-mode`. The generated [API reference](https://github.com/bide-ai/bide/blob/v0.22.0/docs/reference/api/index.md) lists every symbol.
- Changed: `planview.Handler` and `DiffHandler` end in variadic options (code that holds either as a func value of the old type needs a closure); `plan.InspectConfig` and `InspectConfigDescribed` take `...InspectOption`; `plan.Load` and `Validate` name every problem and wrap `agent.ErrConfig`; the `awss3` Reader needs `s3:GetBucketVersioning`, `s3:GetBucketObjectLockConfiguration` and `s3:GetEncryptionConfiguration`, and `awss3.New` refuses a KMS alias as `Config.KMSKeyID`.

Upgrading:

- **Approve page.** Its bundle changed (themes), so its `SHA256SUMS` and Subresource Integrity hash change. If you pin it by hash or host it yourself, update the pin from this release's signed `approve-page.SHA256SUMS` and redeploy.
- **Names.** A flow config identifier with a character that does not print (a control, an invisible or direction-changing character, a joiner or variation selector) is refused. Rename it.
- **Files.** A named pipe, device or directory where a flag expects a file is refused; `-` (standard input), `<(...)` and `/dev/fd/N` still work. Some files now have a size limit, and `plan.LoadReader` and the viewer refuse a flow config over 16 MiB.
- **S3 anchor.** Add the three read actions above to the reader role, or `bide-anchor check` exits 3; switch an alias in `Config.KMSKeyID` to the key's ARN.
- Nothing else changes for existing flows and gates.
