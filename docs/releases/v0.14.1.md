**The real-model step of `bide init` now works first try.**

v0.14.1 is a patch release. It came from running the `bide init` project on a real model (gpt-4o-mini through OpenRouter), and it makes that path work as smoothly as the scripted one.

- **Model nodes use structured output.** A plan flow `Model` node sends its output type's JSON schema to a model that supports structured output (`model/openai`, `model/gemini`), so the reply is exactly that JSON, with each field of the right type.
- **Model nodes retry instead of halting.** A model call has no side effect outside the run, so a `Model` node is now read-only by default: if a call fails or a crash loses its result, the next run calls the model again. A config `safety: side_effect` keeps the halt for anyone who wants it.
- **A smoother scaffold.** The `bide init` README has a "Start over" command that works in bash, sh and zsh, and says when to use it (after switching to a real model). The project's test now runs the story against a fake provider that answers the way real models do.
- **Docs checked against the code.** Every guide, reference page, translation and example README was audited, and the README now says that `bide view` prints the address to open.

Install:

    brew install bide-ai/tap/bide
    go install github.com/bide-ai/bide/cmd/bide@v0.14.1

Behavior changes:

- `plan.Builder.Model` and `plan.Registry.RegisterModel` default to `ReadOnly`. A node that a v0.14.0 process already attempted keeps its attempt marker and still halts once; resolve it with `ResolveHalt` or start a new run.
- A `Model` node's request carries a response format when the model reports that it honours one. An output type that OpenAI strict mode cannot express (a map field, for example) is refused by `model/openai` with `ErrConfig`, as it already is for `agent.OutputNative`.

The CHANGELOG has the details.
