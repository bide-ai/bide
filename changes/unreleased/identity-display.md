Section: Added

Approver identity in the run viewer and the approval commands (build step E3 of the planned approver identity feature; the gate that writes the identity records is a separate step, so no existing gate changes). `bide view` shows, for a gate with a certificate-bound approver, the verified identifier, the certificate's display name, the tier (final with an independent or log-signer time, or PROVISIONAL), the basis, the status time S, when the decision became provable and a dispute (a keyCompromise voiding back to notBefore) on the run page, in the Needs attention list and in the JSON view; a gate paused for status appears as "paused: identity status unknown", and a call held before execution is listed. Only a final tier is drawn in the good style: provisional, recorded-but-not-counted, held, stripped (no identity record) or policy-mismatched identity is never green, and a finished run with such a gate reads IDENTITY NOT FINAL, not VERIFIED. `bide approve -list` prints the same and never shows an identity-bound gate as verified or settled. `bide approve -verify-receipt` (new `-identity-policy` and `-log-key`) and `bide audit verify-receipts` (new `-identity-policy`) now check a certificate-bound receipt against a certificate policy file at the time the decision became provable, and say that revocation status was not checked. New `audit.ReadIdentityPolicy` (the policy file) and `audit.DecisionReceipt.VerifyIdentity`.
