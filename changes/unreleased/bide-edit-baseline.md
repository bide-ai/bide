`bide edit` compares the file with a baseline, the committed policy (the file at git `HEAD`, or at the revision `-base <rev>` names; for a file that is not in git, the file as it was when the editor opened it), with the classifier `bide check -diff -check -fail-on-weaken` runs. A text that is weaker than the baseline shows a banner (`APPROVAL GATE WEAKENED` or `SAFETY CHECK WEAKENED`, each item in the classifier's words) that has no close control, stays until the text no longer weakens and is announced as an alert; a text that cannot be read says it cannot be compared. The `flowedit` module gains `flowedit.ApplyOperation`, the editor's operations on a config's text (a node's safety and block, and its approval gate: `need`, approvers, `exclude_principal`, `timeout`) as verified splices so the diff of an edit is the edit and a gate read back through the check is the gate asked for, an `/api/apply` endpoint for it, `flowedit.Compare` and `flowedit.WithBase`. The page does not offer the operations yet.
