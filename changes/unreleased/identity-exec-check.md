Section: Added

The check of certificate-bound approvers' decisions immediately before a gated call runs, and the operator guide, in the approver identity feature (this change turns the feature on for gates: a policy whose resolver returns an `audit.CertApprover` is now accepted). One function, `preExecute`, re-verifies every counted certificate-bound decision of the gate's outcome with the execution ages and sits on every path to the tool: the base tool handler before the call is begun (so the first execution, a resume, crash recovery, `RecoverLoop` and a middleware retry all pass it) and a plan flow node before its body runs. A decision that is revoked (`E <= A(d)`) or no longer verifies for good writes an insert-once exec hold (`ApprovalExecHoldStep`, with the certificate serial, `E`, reason code and CRL hash) and the next generation is counted, so replacement decisions run the call; status that is missing or stale, or a decision no head covers right now, only pauses (`agent.PendingIdentityStatus`, no record, no approval notification). `audit.CertApprover.VerifyCertExec` applies two tiers by position in the accepted chain: the leaf's issuing CA is judged by `ExecStatusAge`, every CA above it by its own `ExecStatusAgeFor`, which `ValidateConfig` requires with `CAPeriodFor`, `MaxStatusAgeFor` and the new `CAOverlapFor` (`CAPeriodFor + CAOverlapFor <= ExecStatusAgeFor <= MaxStatusAgeFor`); the new values, `MaxStatusAgeFor` and `NotBeforeBackdate` are in the recorded policy and its digest. New `CertApprover.ExecNow` (the execution check's clock), `agent.CertExecVerifier`, `agent.CheckExec`, `agent.CertRevocation` and `audit.ExecLatencyBound`. The guide `docs/guides/certificate-approvers.md` covers declaring the CA's facts from a capture of your own CA, publishing the CRL right after revoking, provisional and final counts, and both revocation latency bounds.
