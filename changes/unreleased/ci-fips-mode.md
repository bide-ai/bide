Section: Added

CI: a "Test (FIPS 140-3)" job runs the Go tests of the modules with `GODEBUG=fips140=only` against Go's in-tree FIPS module and module v1.26.0 (in the merge queue, on main and on a pull request labelled `full-ci`) and against module v1.0.0 (on main), with Postgres and Redis service containers and a live Redis and Postgres test required to pass. Not run under the mode: the SoftHSM2 and PKCS#11 suites, the MinIO Object Lock suite (`anchor/awss3`), the cloud KMS and GCS emulator suites, the `step-ca` container recipe, the browser-driven suites (they have their own Chrome jobs) and the exhaustive or corpus-rewriting tests. Under v1.0.0, which has no ML-DSA, it skips the tests listed in `.github/fips-v1.0.0-excluded.txt` and nothing else, and a check fails when a listed test no longer fails with that error. It is not a required check. New tests in `internal/fipsmode` and `cmd/bide/internal/approvecmd` pin that the approved schemes (Ed25519, ECDSA P-256) work under the mode and that ML-DSA or hybrid under v1.0.0 is an error, not a panic. The documentation states what is tested; bide still makes no claim of FIPS validation.
