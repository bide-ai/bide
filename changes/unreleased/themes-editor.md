bide edit draws from the checked themes, as bide view does. It takes -theme file.json (a custom theme that must pass bide theme check, refused before anything is served if it does not) and -theme-default name, its Theme button steps through light, dark, high-contrast and your theme (naming the next one and announcing the change to a screen reader), a reader whose system asks for more contrast gets high-contrast and one whose system forces colors gets the system's colors, and a program that embeds the editor can lock it to one theme (flowedit.WithThemeLock), which hides the button. The page's own colors now follow the contrast rules: the primary button's text is the theme's on_accent color, the edges of buttons, inputs and the source box use border_strong (3:1 against what they sit on, where the old 1.4:1 hairline did not reach it), every text control, wherever a form puts it, takes the theme's surface and edge, the dialog dims the page with a shadow of the theme's scrim color around it (it needs no support for custom properties in ::backdrop), its box keeps the theme's elevation and a border_strong edge and scrolls inside the screen when its content is tall (forced colors drop shadows, so there it keeps its border and does not dim), and the selected node in the graph is drawn with a 7 px ring in the focus color over its state (its fill and dashes still tell the state; before, a selected gated node was not marked in the graph at all). The Editor (Chrome) job now measures these colors in every shipped theme and system mode, and runs axe-core in high-contrast as well as light and dark.
