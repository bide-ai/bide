Section: Fixed

A named pipe given where bide expects a file no longer hangs it: `bide view` (`-sth`, `-evidence`, `-approver-keys`, `-stop-policy`, `-pubkey` as a file), `bide edit` (a config swapped for a pipe after its check), `bide approve` (`-item`, `-approver-keys`, `-cert`, `-log-key`, `-verify-receipt`, `-tls-ca`), `bide stop -stop-policy`, `bide notify` (`-secret-file`, `-previous-secret-file`, `-client-ca`, `-cert` and `-key`, `-ca`), the webhook notifier's client certificate, key and server CA files, `bide approve -tls-ca`, `-client-cert` and `-client-key`, `bide journal redact` (`-pubkey`, the JSON and signed-head files they read), `bide identity` and the identity preflight (`-policy`, `-params`, `-expect`, certificate chains, the files a policy names) and `bide-anchor -pubkey` open the file without waiting for a writer and refuse anything but a regular file, with the reason; a directory is refused the same way. **Upgrading:** these flags no longer accept a path that is a named pipe, a device or a process substitution (`-pubkey <(vault read ...)`, `/dev/stdin`); to keep a secret off disk, pass `-` where the flag takes it and write the content to standard input: `-pubkey` (bide view, bide journal redact, bide-anchor), `-sth`, `-evidence`, `-approver-keys` and `-stop-policy` (bide view), `-stop-policy` (bide stop), and `-item`, `-approver-keys` and `-log-key` (bide approve). Only one flag can read standard input in a run (a second is refused, naming both), and bide approve needs `-yes` with any of them, since the confirmation would read standard input too. Every other flag listed above takes a regular file only; a file named `-` is written `./-`. Files that had no size limit now have one, and a file over it is refused with a message naming the flag and the limit: 1 MiB for `-pubkey` (bide view, bide journal redact, bide-anchor) and `-log-key`; 16 MiB for `-verify-receipt`, `-tls-ca`, `-client-cert`, `-client-key`, the `bide notify` secret, CA, certificate and key files, `-params` (bide identity and the preflight), `-policy` and the files a policy names, `-expect`, and bide journal redact's `-sth` and `-authorization`; 256 MiB for bide journal redact's `-head-out` file, the append-only log of signed heads (about 650,000 heads at 400 bytes each; a log that outgrows it is refused with the limit named). The limits already in place are unchanged (`-item`, `-approver-keys`, `-stop-policy`, `-cert`, bide view's `-sth`, `-evidence` and journals).
