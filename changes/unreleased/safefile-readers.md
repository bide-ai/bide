Section: Fixed

A named pipe given where bide expects a file no longer hangs it: `bide view` (`-sth`, `-evidence`, `-approver-keys`, `-stop-policy`, `-pubkey` as a file), `bide edit` (a config swapped for a pipe after its check), `bide approve` (`-item`, `-approver-keys`, `-cert`, `-log-key`, `-verify-receipt`, `-tls-ca`), `bide stop -stop-policy`, `bide journal redact` (`-pubkey`, the JSON and signed-head files they read), `bide identity` and the identity preflight (`-policy`, `-params`, `-expect`, certificate chains, the files a policy names) and `bide-anchor -pubkey` open the file without waiting for a writer and refuse anything but a regular file, with the reason; a directory is refused the same way, and files that had no size limit now have one (1 MiB for keys, policies, receipts, parameters and CA files; 256 MiB for the JSON and head files bide journal reads). **Upgrading:** these flags no longer accept a path that is a named pipe, a device or a process substitution (`-pubkey <(vault read ...)`, `/dev/stdin`); to keep a secret off disk, pass `-` where the flag takes it and write the content to standard input: `-pubkey` (bide view, bide journal redact, bide-anchor), `-sth`, `-evidence`, `-approver-keys` and `-stop-policy` (bide view), `-stop-policy` (bide stop), and `-item`, `-approver-keys` and `-log-key` (bide approve). Only one flag can read standard input in a run (a second is refused, naming both), and bide approve needs `-yes` with any of them, since the confirmation would read standard input too. Every other flag listed above takes a regular file only; a file named `-` is written `./-`.
