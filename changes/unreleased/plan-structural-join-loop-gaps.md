Section: Fixed

`bide check`, `bide view -config` and `plan.InspectConfig` without a Registry (the structural check) now report four things that `plan.Load` already refused and the structural check showed no error for, so a config that `bide check` passed could still fail to load: a join that reads a join defined after it in the wiring (Load registers a join when it reaches its wiring element, so the input is unknown; this includes a join that reads itself and a cycle of joins), a switch with more than one loop-back arm (an arm with loop_max above 0), a loop with no exit arm (no other arm and no else), and a loop-back arm whose target is not an ancestor of the switch in the forward graph (the edges, a join's inputs and the arms that do not loop back). Each is an error naming the wiring element. A config that bide check passed and Load refused for one of these now fails bide check too; fix it by defining the input join first, or by pointing the loop arm back at an earlier node of the loop. The other loop checks (a loop body with an inner switch, or with a node between head and switch that is not on the loop path) are still made only when a program loads the flow with its Registry. The editor's lists of approvers and join inputs also had a separate fault, fixed in the same release: a list edit that replaced the items at the start or end of a list deleted and re-wrote the items it meant to keep, losing their comments and turning a block list into a flow list (fixed in bide edit; the approvers list is older than the join inputs list).
