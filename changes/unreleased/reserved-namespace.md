Section: Added

Reserved names for the cap and taint work that follows, and `agent.ErrToolUseIDInvalid`. Run IDs that start with `@cap/` are reserved for cap ledger runs: `Run`, `Stream`, `RunTyped` and `Session` return `ErrConfig` for one, as they do for `@stop`, and `agent.IsReservedRun` (the stop control run or a cap ledger) and `agent.IsCapRun` report them; `Recover`, `RecoverLoop`, the notification sweep and its backfill, the run viewer, `bide approve -list`, `bide audit notifications` and `bide audit redactions` skip such a run. Step names that start with `slot:`, `cap-intent:`, `cap-reserve:` or `gate-reason:` are reserved as well (`Step`, `Parallel` and `ResolveHalt` return `ErrConfig`, `IsReservedStepName` reports them, and redaction treats the four as protected). A live model turn whose tool-use ID holds `#` now fails with `ErrToolUseIDInvalid`, which wraps `ErrModel` and `ErrProtocol` (so `middleware.Retry` and `middleware.Retryable` retry it, and the rejected turn is not journaled); a journal that already holds such an ID still replays. Break risk: a deployment that already runs a run ID under `@cap/` can no longer start it, and the existing run is no longer recovered, listed by the viewer or `bide approve -list`, or read by the audit verbs, so a gate waiting in it would not be shown to an approver; rename such a run before upgrading. A `Step` or `Parallel` task named with one of the four step prefixes in a run that resumes fails with `ErrConfig`, and a model server that sends `#` in a tool-use ID fails every turn that calls a tool. Nothing in the engine writes a ledger or a reason yet.
