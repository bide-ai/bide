Section: Added

A Go program can choose the themes of the pages it embeds. The theme package (github.com/bide-ai/bide/theme, 0.x API; it was internal) parses and checks a theme file as bide theme check does (Parse, Load, Check, Report, Shipped, Lookup), and planview.Handler, planview.DiffHandler and flowedit.New take planview.WithThemes, WithDefaultTheme and WithThemeLock (the same three in flowedit): extra themes beside light, dark and high-contrast, the theme a reader starts in, and a lock that makes one theme the only one (no switch, no remembered choice). A host passes only values that passed the checks: it cannot give CSS or a selector, the stylesheet generators are not exported, and a reader whose system asks for more contrast or forces colors still gets those over a default and over a lock (a Chrome test holds both). Upgrading: planview.Handler and planview.DiffHandler now end in a variadic opts ...Option, so a call is unchanged but code that holds either function as a value of the old func type (a struct field, a variable, an interface method) no longer compiles; wrap the call in a closure. A bad set of themes (a nil or foreign theme, a repeated name, an unknown default or lock) panics when planview builds the handler and makes flowedit.New return an error. Measure has a String method, the line bide theme check prints for a measure.
