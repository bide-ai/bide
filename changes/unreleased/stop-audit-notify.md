`bide audit notifications -db` (and `-postgres-env`) checks the kill switch's notifications from the control run: every stop in force must have been told (`stop_set`), whatever its recorded time says (a record's time is its writer's own, so a backdated or future-dated stop is still owed; `-stops-within`, default 7 days and the notifier's window, limits only stops that are over, and `NotifyPending` now notifies every stop in force the same way), a lifted stop owes its all-clear and its `stop_lifted`, and a stop set and lifted before any notifier looked owes only the lift; a stop or lift no notifier saw fails with `never_notified`, and a control run the audit cannot judge (signed records and no `-stop-policy`) is refused with exit 4 instead of passing what it did not check. `-stop-policy` and `-stop-root` read the control run as the deployment pins its policy. `audit.VerifyNotifications` takes the control run's state as `NotifyVerifyInput.Stops` (judged with `agent.StopNotifyEvents`, which shares its window rule with the notifier) and reports a control run record dated in the future, or well before an earlier record, as a problem (`StopAnomalies`, `agent.StopClockAnomalies`); with `-run` the command prints an INFO line that stops were not checked and now reads the `stop_set` and `stop_lifted` kinds, the all-clear reason `lifted` and the stop key shapes, which it refused as unknown before (`agent.ParseStopKey`). Guide: docs/guides/notifications.md.
