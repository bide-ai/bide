`bide audit notifications -db` (and `-postgres-env`) checks the kill switch's notifications from the control run: every stop set within `-stops-within` (default 7 days, the notifier's window) must have been told (`stop_set`), a lifted stop owes its all-clear and its `stop_lifted`, and a stop set and lifted before any notifier looked owes only the lift; a stop or lift no notifier saw fails with `never_notified`, and a control run the audit cannot judge (signed records and no `-stop-policy`) is refused with exit 4 instead of passing what it did not check. `-stop-policy` and `-stop-root` read the control run as the deployment pins its policy. `audit.VerifyNotifications` takes the owed events as `NotifyVerifyInput.StopEvents` (`agent.StopNotifyEvents`, which shares its window rule with the notifier) and now reads the `stop_set` and `stop_lifted` kinds, the all-clear reason `lifted` and the stop key shapes, which it refused as unknown before (`agent.ParseStopKey`). Guide: docs/guides/notifications.md.
