Section: Changed

A redaction can now erase an end marker (`run:complete`, `run:aborted`, `run:cancelled`), by naming it (`bide journal redact -name run:complete`), so the run's final answer, or its cancellation or failure text, can be erased. `-payloads` does not select an end marker, and its dry run says so (`end marker not selected by the Payloads preset: name run:complete to erase its content`), so nothing is left behind silently. The tombstone keeps the marker's position, and every reader finds the run over by it, but none reads how the run ended from it, because a tombstone's name is outside the leaf hash and a rename would flip a completed run to cancelled: `agent.Status` reports the new state `agent.RunEnded` with `agent.RunStatus.EndRedacted` set and no `Terminal` text, `IsComplete` is false, `Cancel` reports `ErrRunEnded`, `Recover`, `RecoverLoop` and a drive treat the run as over and refuse to drive it, the notifier does not raise an abort from an erased `run:aborted`, `bide view` shows `ENDED (ERASED)`, and a flow's `Conform` does not compare an erased completion. Only the signed redaction trail records what the marker was (`bide audit redactions`, `NAME_MISMATCH` for a rename). `agent.RedactionProtected` no longer lists the end markers; a tombstone at any other `run:` name is still corruption. On Postgres the redaction function moves to `bide_redact_v3`, which allows the end markers; the migration creates it and revokes `EXECUTE` on every older `bide_redact_vN` from PUBLIC and every grantee, so only the current function is callable, and you grant the erasing role `EXECUTE` on `v3` (the store calls only `v3`). The lifecycle model gained the erasure (`RedEnd`, model 10): `life-redact` passes, `regress/redacted-not-end` and `regress/redacted-kind-from-name` show the two bugs (reading an end by content, reading its kind from the name).
