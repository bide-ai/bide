Design only: TLA+ model 14 (`spec/tla/notify`) of the notifier design's notify-once trail (observed, one claim per delivery round, acked, failing, overdue, cleared, failing_since, recovered) over processes, crashes, lost replies, trail appends that error, claims that lapse mid-send and the lost append race. It checks no silent drop, a duplicate bound of 1 + crashes + lost replies + mid-round lapses, no concurrent double under a live claim, overdue by the deadline, `recovery_failing` under a crash loop, idempotent `acked` and `cleared`, and, composed with model 10, that the notifier never changes the run lifecycle. A regression configuration per property breaks its rule and must fail. It found N1: a failure count kept in process memory is reset by a restart, so `failing` comes late and, under a crash loop, never (`overdue` still fires); counting failed rounds from the trail's `claimed` records fixes it. `spec/tla/check.sh` gains `SPEC`, `LIBRARY` and `EXPECT: action` configuration lines, and a pull request that changes model 10 re-checks model 14.
