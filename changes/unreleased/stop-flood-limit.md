Section: Changed

A writer with store write access cannot stop a kill switch stop from landing, but can slow it: every full read of the control run folds every entry, so `SetStop`, `State()` and a `StopSwitch`'s first read grow linearly (a switch's later reads are incremental and stay cheap until new entries arrive) with the junk entries a writer adds under `@stop/set/` (measured, one global `SetStop` with 100,000 junk entries: 0.84 s on SQLite, 2.0 s on Postgres; with 10,000: 0.1 s and 0.15 s). This is now stated in the kill-switch guide and in the known limitations, and a guard test on SQLite (and on Postgres with `PG_DSN`) fails if 10,000 junk entries push any of these calls past 2 seconds or make one grow faster than linearly from 2,500 entries. Keep the control run's store writable only by the processes that operate the kill switch.
