Section: Changed

The awss3 Reader now audits the bucket itself: Audit reads its versioning, Object Lock configuration and default encryption and reports a finding for versioning that is not enabled, Object Lock off, a missing default retention or one under 24 hours, and, through the new ReaderConfig.KMSKeyID, Retention and Mode expectations, a default retention shorter than configured, a default mode weaker than configured, a default encryption that is not the expected KMS key, and an object that is not encrypted with it or is retained for less than the expected retention from its own write; bide-anchor -backend s3 takes the same as -kms-key, -retention and -lock-mode. The shipped reader policy gains exactly the three read actions this needs (s3:GetBucketVersioning, s3:GetBucketObjectLockConfiguration, s3:GetEncryptionConfiguration), so a reader whose policy lacks them now gets an access error on the bucket read, and bide-anchor check exits 3 (state unknown) instead of passing: add the actions to the reader role.
