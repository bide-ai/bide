Section: Fixed

The relay's state file write copes with another process holding the file open on Windows: replacing `relay.state` fails with a sharing violation or access denied while a reader (an operator's `tail`, a virus scan) has it open, and the save is now retried on a timer within milliseconds (about 300 ms in all, not logged, no request waits for it). A save that fails for any other reason is no longer forgotten until the next event: the state stays pending and is written again after the flush delay (at least a second, doubling to 30 seconds while it keeps failing, logged once per streak and again when it recovers), or at `Close`. The test that polled the file for the flush no longer fails on the same transient open error.
