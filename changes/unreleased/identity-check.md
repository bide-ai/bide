`bide identity check` is the pre-flight for a certificate-bound approval setup, for a bank to run before go-live and an approver to run when a decision is refused. It reports one line per check, with the fix, or the same as JSON (`-json`): the policy file loads and its pinned CAs and intermediates are valid and match their certificates; the declared CA timings pass the gate's own configuration check; the policy file and `-params` agree member by member with the policy record the gate journals (`-expect`), with the members `-params` cannot declare listed as not verified; the CRLs, read offline from a `fetch-crl` archive or a flat directory (`-crl-dir`, never written) or fetched with the refresher's own limits (`-fetch`), are fresh by the refresher's health model and the status rule's freshness test; and, for an approver's chain (`-cert`), whether the gate would accept it and let the call run, with the gate's own reason if not. It never reports ready while a part was left out: `-no-status` and `-no-expect` give a partial result (exit 4), a failed check exits 1, a usage error 2, an unreadable file 3. Every report lists what a pre-flight cannot check ahead of time. The chain verdict is `audit.CertApprover.CheckCertificate`, the function the gate's counting and execution checks call.
