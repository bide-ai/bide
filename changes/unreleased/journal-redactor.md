Section: Added

Added the optional `agent.Redactor` store capability, implemented by `MemStore`, `store/sqlite` and `store/postgres`, which replaces one entry of a finished run with a redaction tombstone that keeps its position and audit leaf hash, together with `agent.PlanRedaction` (a dry run that lists records by position, name and leaf hash and never their content, with a digest), `agent.Redact`, `agent.NewTombstone`, `agent.LeafHash`, `agent.CheckRedaction`, `agent.RedactionProtected` and `storetest.Redactor`, the conformance suite. A store refuses, writing nothing, a run with no end marker, a run with a live lease, a protected record (the journal header, end markers, attempt markers, saga failures and the records an approval count rests on), a tombstone that does not keep the leaf hash of the bytes it replaces (the store recomputes it), and an entry that changed since the caller read it. The core `Store` port is unchanged. `agent.Status` now reports a run whose `run:start` was redacted as started rather than not started. A Postgres role with `UPDATE (data)` on `bide_steps` alone does the erasing, so the application's role still cannot. There is no command yet and the erasure is not yet recorded in an audit trail; see the retention guide's section on erasing personal data for what it does not reach.
