Section: Fixed

`bide check -diff -fail-on-weaken` (and `planview.CheckDiff`) now exits 1 when a change makes a node reachable around an approval gate whatever the node's `safety`: any node that every path reached through an approval gate before, and that some path now reaches without one, is reported as weakened, with the node, its safety and the shortest ungated path. Before, only nodes labeled `side_effect` or not stated counted, so an `idempotent` node that moves money, or the same edit relabeling the node `readonly` and adding the bypass, exited 0. A `safety` moved toward read-only (side effect or unknown to idempotent or read-only, idempotent to read-only) is itself reported as weakened (`Change.Weakening` gains `safety`), the old label counts as well as the new one in the effect checks (the new-effect rule and the Switch-arm rule), and a node renamed together with a safety change is still paired as the same node and judged on both; a new node that shares a removed node's block and kind is also judged against it, and a new node reachable without a gate that uses a block every node used only behind a gate before is reported whatever its name and label. A configuration that wires a read-only node in around a gate will now see `-fail-on-weaken` fail where it did not.
