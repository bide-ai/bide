Section: Added

`bide edit flow.yaml`, the first release of the flow editor (`docs/design/visual-editor.md`), is read-only: a local page, served by the binary on a loopback address, shows a flow config's declared graph, an outline of its nodes and wiring in config order, the selected node's block, safety, crash behavior and approval gate, the assertions with their verdicts and counterexamples, the problems `bide check` finds and the source, all computed by the code `bide check` and `bide view -config` run and labeled as the structural check. The page is hand-written script and the viewer's styles, served from the binary under a Content-Security-Policy that allows only same-origin resources; every request is a POST of JSON from its own origin with a per-run session token (printed in the address's fragment), and the command reads only the file it is given (a `.yaml`, `.yml` or `.json` regular file of at most 1 MiB). It is in the full `bide` binary and not in a `bide_audit_only` build. A Go program can embed the page: `flowedit.New(path).Handler()` is an `http.Handler`, and `flowedit.BuildView` is the page's data for a text. A new Chrome job (`Editor (Chrome)`) drives the page and fails on a console error, a Content-Security-Policy violation or a request off the page's origin. Documented in the new [flow editor guide](docs/guides/flow-editor.md).
