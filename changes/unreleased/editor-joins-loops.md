Section: Added

bide edit can set an arm's loop bound and add, change and remove joins (the fourth step of the editor's structure phase). A loop bound is a number above 0 on a switch arm (0 removes it); a join is added from a disclosure under the outline (a name, a merge block and its inputs) and edited on its own inspector: the merge block, the inputs in order (add, move, remove), the same safety and approval gate forms a node has (written on the join's wiring element), and edges out of it. Removing a join lists what goes with it (the edges out of it, a switch on it, its comments) and needs that list confirmed, as removing a node does, and a node that is an input of a join is still not removed. The editor checks what the config says (an input is a declared node or join, named once, not the join itself); it cannot check that a merge block is registered or that its arity and types fit the inputs, which plan.Load does with the registry. New joins are written as `inputs: [a, b]` where the file has none to copy. The keyboard test no longer walks the whole page to the assertion form: it uses the skip links. The API gains the operations add_join, remove_join, set_join_inputs, set_join_merge and set_loop_max, Operation.Inputs and Operation.Max, and set_safety, set_approval and clear_approval accept a join's name.
