`bide-hsm` takes a `gcpkms:projects/<p>/locations/<l>/keyRings/<r>/cryptoKeys/<k>/cryptoKeyVersions/<n>` key reference for an approver key in Google Cloud KMS: the numeric version is pinned (an alias, `latest`, a query or a malformed name is refused, and the error repeats no value from the reference), credentials are Google's application default credentials, only an HSM-backed version is used unless `-allow-software-key` (Cloud KMS has no HSM-backed Ed25519 key, and `bide-hsm approve` says beside the key when it is at protection level SOFTWARE), and `-verify-attestation` requires the version's Cloud HSM attestation. Tested against gcp-kms-emulator v0.10.0 in the test process (in the test-only module `cmd/bide/bide-hsm/emulatortest`, which keeps the emulator out of bide-hsm's module graph), never against Google Cloud.
