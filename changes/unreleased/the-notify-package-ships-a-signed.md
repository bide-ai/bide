Section: Added

The `notify` package ships bide's webhook notifier, `notify.NewWebhook`, an `agent.Notifier` that delivers a notification as a signed HTTPS POST of a `bide.notification.v1` JSON payload. The payload holds structured fields only (kind, run, step and tool name, the approval gate's approver IDs and k of n, the run's principal, times and a `bide view` pointer): no error text, tool arguments or approve link, unless the operator names fields in `WithFields(notify.ErrorText, notify.Args("refund"))`. Each request carries `Bide-Delivery` (the stable notification ID), `Bide-Timestamp` and `Bide-Signature: v1=<hex HMAC-SHA256(timestamp.body)>`, one entry per secret so a secret can be rotated with `WithSecrets(current, previous)`. `notify.Verify(r, secrets, tolerance)` checks a request in one call for a receiver (5 minute default timestamp tolerance, constant-time compare, body left readable). Transport is HTTPS only (`http` only for localhost, 127.0.0.1 and [::1]), never follows redirects, times out per request, makes up to 3 requests per round with backoff, honors `Retry-After` on a 429, and requires TLS 1.2 or newer. Optional mutual TLS (`WithClientCert`, reloaded when the files change without a restart, keeping the last good pair if a reload fails), `WithServerCA` (replaces the system roots) and `WithServerPin` (SPKI SHA-256, up to two) add to the signature and never replace it. Each accepted delivery reports how it was authenticated (signature scheme and secret slot, never a secret; the client certificate's SPKI hash; custom CA or pin; negotiated TLS version) for the `auth` field of the trail's `acked` record. See the new [notifications guide](docs/guides/notifications.md) for Slack and PagerDuty adapters.
