`bide-hsm audit stops -sign-head -log-key <key ref> -head-out <file>` signs the kill switch's stop-trail head with a log key held in an HSM or a cloud KMS (a `pkcs11:` URI, `awskms:`, `gcpkms:` or `azurekv:` reference), closing the gap that `bide audit stops -sign-head` took a key file only. It is the same verb as `bide audit stops` (one implementation in `internal/auditcli`): it signs only the records it verified against the pinned policy and the control run, signs nothing when the audit is not clean, adds nothing when the newest head already commits to every record, opens the key only when there is something to sign and only after checking it is the key `-pubkey` names, and has the same exit statuses; the heads it writes verify with the existing verifier. The reference holds no secret (a PKCS#11 PIN comes from `pin-source`), and the key flags of `bide-hsm approve` apply. `bide-hsm audit` runs the `stops` verb only. Guide: docs/guides/kill-switch.md.
