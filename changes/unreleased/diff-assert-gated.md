Section: Fixed

`bide check -diff` (and `planview.CheckDiff`) now reports weakenings it missed, and `-fail-on-weaken` exits 1 on them: an `assert` line removed or loosened (an approval assertion with a lower K, a larger N, or without `excluding the requester`; a tightened one is a strengthening); any node that may have an effect (safety `side_effect`, or not known) and is reachable without an approval gate when it was not such a node before, whether through a new arm around a gate, a gate removed upstream, a raised or dropped `safety`, or as a new node (reported with the ungated path, from the same reading as `ConfigReport.Gated`); a Switch arm condition changed beside an arm that leads to an ungated effect (predicates are not readable, so it asks for a review); and, without a `plan.Registry`, a block changed on an ungated effect node. A node renamed with the same block, safety, gate and edges is reported as `renamed`, not as a removed gated node and a new ungated one. `DiffView` and each `Change` gain a `weakening` field (`gate`, `path`, `block`, `condition` or `assertion`), the page's verdict reads `SAFETY CHECK WEAKENED` when no gate policy itself was weakened, and `plan` gains `CompareAssertions` and `ConfigReport.UngatedPath`.
