Section: Fixed

`bide check -diff` (and `planview.CheckDiff`) now reports weakenings it missed, and `-fail-on-weaken` exits 1 on them. Behaviour change: a node that may have an effect (safety `side_effect`, or not stated) and is reachable without an approval gate, when it was not such a node before, is now a weakening, whether through a new arm around a gate, a gate removed upstream, a raised or dropped `safety`, or as a new node, so a config that leaves `safety` out will see `-fail-on-weaken` fail on new or changed unknown-safety nodes; state `safety: readonly` where it holds (the example refund flows now do). Also reported: an `assert` line removed or loosened (an approval assertion with a lower K, a larger N, or without `excluding the requester`; a tightened one is a strengthening); a Switch arm condition changed beside an arm that leads to an ungated effect (predicates are not readable, so it asks for a review); and, without a `plan.Registry`, a block changed on an ungated effect node. A node renamed with the same block, safety and edges is reported as `renamed` (with its gate change, if any), not as a removed node and a new one. `DiffView` and each `Change` gain a `weakening` field (`gate`, `path`, `block`, `condition` or `assertion`), the page's verdict reads `SAFETY CHECK WEAKENED` when no gate policy itself was weakened, and `plan` gains `CompareAssertions` and `ConfigReport.UngatedPath`.
