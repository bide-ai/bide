Section: Added

`bide-hsm csr -key <ref>` writes a PKCS#10 certificate signing request for a key held in an HSM or a cloud KMS, signed by that key through the same key sources as `bide-hsm approve` (PKCS#11, AWS KMS, Google Cloud KMS, Azure Key Vault; Ed25519 or ECDSA P-256 as the source has them), so an approver no longer needs the vendor's tooling to get a certificate for it. The request names nothing by default; `-san-email`, `-san-uri` and `-eku` ask for a SAN and a usage, and `-policy <file> -as <approver>` asks for exactly what the gate's identity policy looks for and prints what the CA must issue. Before it writes, it checks the request's signature, that its public key is the key source's, and that it carries only the names asked for; it writes to `-out` or standard output and never overwrites a file without `-force`. `bide keygen -csr` now builds its request through the same code. Ed25519 and P-256 only: there is no RSA request.
