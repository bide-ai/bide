`bide notify` sets up and tests the webhook notifier. `bide notify test` sends one signed sample notification to a receiver through the notifier's own code path (payload, signature, TLS 1.2+, private CA, key pin, mutual TLS) and reports the TLS handshake, the HTTP status, whether the receiver acknowledged and the timing, with a next step for each failure; `bide notify listen` is a local HTTPS receiver with a self-signed certificate (it prints the CA file and pin) that verifies each request with `notify.Verify` and prints the event; `bide notify relay` verifies bide's webhooks and forwards them to Slack (a Block Kit message with the run, kind, summary, deadline and a viewer link) and PagerDuty (Events API v2 trigger keyed by the event ID, with a hook for resolving on an all clear). The relay answers 502 when a forward fails so the notifier retries, drops redeliveries by delivery ID in a bounded cache, retries only the destination that failed, never forwards error text or tool arguments, and never logs a secret or a webhook URL. Secrets are read from an environment variable or a file, never a flag. The relay is also a library, package `notify/relay` (`relay.Handler`, `relay.Sink`, `relay.NewSlack`, `relay.NewPagerDuty`), and `notify.Webhook.Probe` reports a delivery's handshake, status and timing for tools that test a receiver.
