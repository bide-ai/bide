`bide approve -to <url>` (and `bide-hsm approve -to`) decides through an application's approval intake (`approvals.Handler`) instead of writing a journal: it fetches the pending call from the endpoint, shows it, signs the digest of the arguments it computed from what it showed (and refuses an endpoint whose own digest differs, or whose tool, arguments or gate differ after the confirmation), and posts the decision, so the application records it through its own journal and its audit log signs it as it is written. A decision the endpoint says does not count is a failure, as in the local flow. The URL must be https (http only to loopback), a redirect is not followed, and `-tls-ca`, `-client-cert` with `-client-key`, and `-token-env` cover a private CA, mutual TLS and a bearer token. The endpoint returns the decision's receipt, which the command checks against what it signed, and refuses if it carries an anchoring proof, before writing it.
