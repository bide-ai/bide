`bide approve -to <url>` decides through an application's approval intake (`approvals.Handler`) instead of writing a journal: it fetches the pending call from the endpoint, shows it, signs the digest of the arguments it computed from what it showed (and refuses an endpoint whose own digest differs), and posts the decision, so the application records it through its own journal and its audit log signs it as it is written. The URL must be https (http only to loopback), a redirect is not followed, and `-tls-ca`, `-client-cert` with `-client-key`, and `-token-env` cover a private CA, mutual TLS and a bearer token. The endpoint returns the decision's receipt, which the command checks against what it signed before writing it.
