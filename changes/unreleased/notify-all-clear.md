The notifier now sends an all-clear. When an `outcome_unknown`, `approval_pending` or `recovery_failing` event that a receiver was, or may have been, told of stops being current (the halt was resolved, the gate decided, the run ended, recovery recovered), a `resolved` notification (`agent.NotificationResolved`) is delivered with the same audited claim and acknowledgement trail, at-least-once delivery, stable ID and retry as any event, so a PagerDuty incident, ticket or Slack thread can be closed. It names the event it ends in `Notification.Clears` (`Key`, `ID`, `Kind`) and the reason in `Notification.Reason`; in the webhook payload that is a `clears` object (`id`, `key`, `kind`, null on every other kind) and the existing `reason` field, and `deadline_at` is null. The ID of the event is final: a receiver treats every delivery of that ID, before or after the all-clear, as superseded, which is how an all-clear that arrives first is matched. It is never overdue (no deadline, no overdue notice) and is retried like any delivery. An event never claimed, and `run_aborted`, get none. It is found by a scan of the run's trail after every drive of a root run, every recovery pass and every run `NotifyPending` lists (one trail read each, off the drive's path). Receivers that treated every webhook POST as a new alert should filter on `kind`. TLA+ model 14 gains the all-clear (`Clears`, key `r_<event>`) with its safety and liveness properties, regression configurations and the ordering limit (`limits/clear-before-event`).
