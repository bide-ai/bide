Section: Added

New module `github.com/bide-ai/bide/flowedit`, the edit engine of the planned flow editor (`docs/design/visual-editor.md`): `flowedit.Apply` changes one value, entry or item of a flow config's YAML or JSON text by splicing, so every byte outside the edit is the original byte, comments, key order, flow-style mappings and blank lines survive, and the diff of an edit is the edit. It returns text only after `Verify` re-parses it and checks that its data, key order, untouched lines and comment ownership are the old text with the operation applied; anything it cannot splice safely (an anchor or alias anywhere in the document, merge keys, a repeated key or a key that is not a string, NaN and infinity, a string that is not UTF-8, tags, more than one document or text after the document, CRLF, a byte-order mark, non-UTF-8 text, a document that is not a mapping) is a `*Refusal` and the text is untouched. All text leaves through one function that a test pins. Measured over 367 configs and 65,951 operations, 99.2 percent of operations applied and touched only the intended lines, against 18.4 percent for a re-emit through `yaml.Node`, with no unverified output in 4.5 million fuzz executions. There is no command yet; `bide edit` follows. It is not published yet: it joins the published modules when `bide edit` requires it.
