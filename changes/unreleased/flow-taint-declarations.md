Section: Added

Plan flows enforce a taint policy (experimental, Go only). `Builder.WithTaintPolicy` (or `plan.WithLoadedTaintPolicy`) gives a flow an `agent.TaintPolicy`, and `plan.Untrusted`, `plan.Trusted`, `plan.TaintExempt`, a tool's own declarations and the `untrusted` key of a config node say what each node's results carry. Once a run has read untrusted content (a node that declares a source, the run's input when `WithUntrustedInput` names it, or what a flow a node started brought up), a node that can have a side effect needs the policy's escalation gate on a second subject, `node:<name>:taint`, before its attempt claim, or is refused under `Refuse` (`plan.ErrTaintRefused`). The run records its declarations in `run:start`, a drive under other declarations is `ErrConfig`, and `Flow.Conform` checks that every node that ran met its obligation. A flow a node's body starts inside a run under taint inherits the status and marks as an agent child does, and sends the marks it learned up to that node (`taint-mark:` and `taint-child:` records), also when `ResolveHalt` records the node's result. `Build`, `Load`, `Validate` and `bide check` no longer refuse a flow that declares taint, and a flow block whose tool declares `Untrusted` or `TaintExempt`, refused before, is accepted. Not built: `SeparateApprovers`, and the marks of an agent a node's body runs. Do not drive a run that started under a flow taint policy with v0.25.x or earlier: they do not read the taint records and run a node this release refused or held at its gate (see KNOWN-LIMITATIONS).
