Section: Added

`bide edit` lets you edit the config's source in the page and save it. Typing asks the server for the `bide check` verdict of the new text, so the graph, outline, assertions, problems and the weakened banner follow the text; nothing is written until Save, which opens a dialog with the plain unified diff of the bytes against the file on disk, every comment the diff removes, the number of errors (a file with errors can be saved, and the dialog says it will fail `bide check`), and, for a text weaker than the baseline or one that could not be compared, the items to confirm: the server refuses a save without exactly that confirmation, and one made for an older text does not cover a newer one (HTTP 422, nothing written). The write is atomic (a temporary file in the same directory renamed over the file, keeping its permission bits, leaving the old file and no debris on a failure); the page carries the hash of the file as it read it, and a file that changed on disk since is a conflict (HTTP 409) that shows the file against the author's text and is never overwritten; the path is fixed at startup and checked again at write time (a symbolic link or a directory in its place is refused). The editor never runs git. New in the `flowedit` module: `(*Server).Preview` and `(*Server).Save`, `UnifiedDiff` and `RemovedComments`; the guide and `docs/KNOWN-LIMITATIONS.md` say what a rename-over save does not keep (hard links, extended attributes, ACLs) and that the check is compare-and-swap, not a lock.
