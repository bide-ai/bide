`bide stop`, the kill switch's command line (and `bide-hsm stop` for a key in an HSM or a KMS): `-all`, `-tool`, `-flow` and `-agent` set a stop (there is no default scope, and a bare `bide stop` lists the active stops and exits 2), `-list` (with `-json`), `-show`, `-lift`, `-reaudit`, `-apply-pending`, `-upgrade` and `-downgrade` work on it. Basic mode needs no keys; audited mode (`-stop-policy`, `-as`, `-key`) signs each record with an enrolled approver's key, checks the key and role before writing, and lifts by the policy's quorum. A stop is written without a prompt when `-yes` is given or stdin is not a terminal; a lift and the configuration operations ask on a terminal and refuse without one unless `-yes`. Exit statuses are 0, 1, 2, 3 and 5, where 5 means an audited record landed in the control run or on the trail but not both (`-reaudit` and `-apply-pending` complete it). No secret goes on the command line: a key is a file or a key reference, a Postgres journal is named by its DSN variable. `bide audit stops` gains `-sign-head -log-key -head-out`, a schedulable job that verifies the stop trail against the control run, signs a head over exactly the verified records (`audit.SignStopTrailExport`) and appends it to a head file that `-sth` reads; a deployment must run it, or the audit fails on the unattested tail. Guide: docs/guides/kill-switch.md.
