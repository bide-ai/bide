The kill switch's engine side (`agent.StopSwitch`, `agent.WithStopSwitch`, `*agent.Stopped`, `agent.WithRecoverStop`): an agent given a switch holds a covered run, as a pause, at a drive's start, at a turn's start, before a call's claim, after the claim and immediately before the call begins, so no side effect starts under a stop that was committed before the check; a won claim that is held is recorded as not started, a call that has begun finishes and is journaled, a written attempt marker is never fired again by a stop or its lift, and a saga's rollback continues unless the stop blocks compensation. A side-effect call reads the control run itself and is held (fail closed) when it cannot be read past a staleness bound, or when the stops cannot be judged; Recover and RecoverLoop list nothing during a global stop. An agent without a switch on a store whose control run holds a record fails its drives with `ErrConfig`, which costs one extra Load per store every few seconds on a drive (the budget tests count it). Model 16 maps the check points. A plan flow takes a switch with `Builder.WithStopSwitch` (or `plan.WithLoadedStopSwitch`): a flow-scope stop holds a run at its start and each node before its claim and after it, with the same not-started record, and a flow without a switch on such a store is refused. A multi-handle Postgres test shows a stop set by one process holds another's next side-effect call. Guide: docs/guides/kill-switch.md.
