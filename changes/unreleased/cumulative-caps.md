Section: Added

Cumulative amount caps: `agent.WithCaps` now accepts `sum N CUR per run|hour|day [by key] -> refuse` (a tool that carries one reserves each call's amount in a cap ledger, a reserved journal run under `@cap/`, after its attempt is claimed and before the tool begins, and the call that would take the window over its limit is refused as a known failure the model reads, with the tool not called), and `agent.WithCapNamespace` names the deployment's ledgers (default `default`). A store that cannot be read or written fails the call before the tool is begun, so a cap is fail closed; an amount of zero reserves nothing; a negative, absent or unparseable amount, a missing key, or a key with a byte outside ASCII is refused. A call that may have run stays counted, so a window only over-counts. The loop releases the slot of a not-retry-safe call it proved never began (it seals the call's began word first, and releases before it records the attempt as not started), and `Recover` and `RecoverLoop` release the slot of an attempt recorded as not started; a call that began, an `Idempotent` call, a `ResolveHalt`ed call and a saga's rollback are never released. `-> gate` is still refused at registration. See the amount caps guide.
