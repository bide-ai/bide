Section: Added

Cumulative amount caps: `agent.WithCaps` now accepts `sum N CUR per run|hour|day [by key] -> refuse` (a tool that carries one reserves each call's amount in a cap ledger, a reserved journal run under `@cap/`, after its attempt is claimed and before the tool begins, and the call that would take the window over its limit is refused as a known failure the model reads, with the tool not called), and `agent.WithCapNamespace` names the deployment's ledgers (default `default`). A store that cannot be read or written fails the call before the tool is begun, so a cap is fail closed; an amount of zero reserves nothing; a negative, absent or unparseable amount, a missing key, or a key with a byte outside ASCII is refused. A call that may have run stays counted, so a window only over-counts, and in this version nothing releases a reservation: a call refused or cancelled after it reserved keeps its amount counted until the window ends. `-> gate` is still refused at registration. See the amount caps guide.
