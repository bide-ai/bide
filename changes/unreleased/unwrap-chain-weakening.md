Section: Security

`agent.New`, `With` and the plan registry's `RegisterTool` now refuse, with `ErrConfig`, a tool wrapper (a tool with an `Unwrap() Tool` method) whose own `Spec` weakens the approval gate or the `Timeout` of a tool on its `Unwrap` chain, however it holds that tool (a named field was not seen before: the outer `Spec` won, so a gate the wrapped tool declared silently did not apply). Weaker means no gate, fewer decisions needed, a `SingleApproval` over an m-of-n gate, an approver the wrapped gate does not name, no `ExcludePrincipal` where the wrapped gate has it, no gate deadline or a longer one, and for the tool's `Timeout` none or a longer one. This changes behaviour for a wrapper that dropped or loosened a declaration: declare the same on the wrapper, or build its spec from the wrapped tool's. Not checked through the chain: `Safety` (a wrapper may legitimately raise it, so the rule needs a design decision; until then not declaring a weaker `Safety` than the wrapped tool is the wrapper author's duty, as a `ReadOnly` claim over a side-effecting tool loses at-most-once protection), and not yet `Untrusted` or per-call caps. Also fixed: a wrapper whose `Unwrap` returns a typed nil pointer no longer panics registration or sub-agent lookup; it ends the chain.
