`postgres.WithoutMigration` opens the Postgres store (and `New`) without running the schema migration, so the application's database role needs no `CREATE` on the schema: it verifies the schema and refuses a missing one (`postgres.ErrSchemaMissing`) or one at another version (`postgres.ErrSchemaVersion`) without creating or altering anything. `postgres.Migrate` and `MigrateDB` run the migration on its own and report the schema version before and after, what they created and the SQL (`postgres.WithDryRun` rolls it back), and the new `bide migrate -postgres-env VAR [-schema S] [-dry-run]` command runs it as the owner role with the DSN read from the environment. `OpenReadOnly` now returns the same typed errors. The Postgres store guide (`docs/guides/postgres.md`) documents the owner, application and reader roles; the governed log has the same split (`postgreslog.WithoutMigration`, `postgreslog.Migrate`, `postgreslog.ErrSchemaMissing`), and the log now records a schema version in `governed_events_schema_version` (a log without the table is version 1, and `Migrate` or a migrating `Open` adds it) and refuses another with `postgreslog.ErrSchemaVersion`.
