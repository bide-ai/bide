Section: Changed

awss3.New now accepts only a key ID (a lower-case UUID), a multi-Region key ID (mrk- and 32 lower-case hex digits) or a key ARN as Config.KMSKeyID, and refuses everything else, an alias (alias/name or an alias ARN) above all, with an error wrapping agent.ErrConfig, because S3 reports the ARN of the key an alias resolves to and the read-back that checks each head's key could not tell which key it was: an alias used to match any key. Upgrading: a deployment configured with an alias must switch Config.KMSKeyID to the key ARN, or New refuses to start with the error `awss3: Config.KMSKeyID: KMS key must be a key ID or key ARN (got "alias/..."): a lower-case UUID, mrk- and 32 lower-case hex digits, or arn:<partition>:kms:<region>:<account>:key/<one of those>, with no spaces or other characters; for an alias, pass the ARN of the key it points to: config`, which you can search your logs for; an upper-case key ID, a key ID with a leading or trailing space and any other string that is not one of those forms are refused the same way (a key ID or key ARN in the forms above works as before). The Reader (ReaderConfig.KMSKeyID) and bide-anchor -kms-key apply the same allow-check.
