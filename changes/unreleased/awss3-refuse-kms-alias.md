Section: Changed

awss3.New now accepts only a key ID (a UUID), a multi-Region key ID (mrk- and 32 hex digits) or a key ARN as Config.KMSKeyID, and refuses everything else, an alias (alias/name or an alias ARN) above all, with an error wrapping agent.ErrConfig that says to pass the ARN of the key the alias points to, because S3 reports the ARN of the key an alias resolves to and the read-back that checks each head's key could not tell which key it was: an alias used to match any key. Upgrading: a deployment configured with an alias must switch Config.KMSKeyID to the key ARN, or New refuses to start with an error that starts "awss3: Config.KMSKeyID" and says "is not a KMS key ID" and "pass the ARN of the key the alias points to" (it wraps agent.ErrConfig), which you can search your logs for; a key ID or key ARN in the forms above works as before. The Reader (ReaderConfig.KMSKeyID) and bide-anchor -kms-key apply the same allow-check.
