Section: Added

`bide view` shows the kill switch: while a stop is in force every page of a store opens with a banner (scope, reason, setter, age, lifts held and needed, the mode), and the banner also appears when the stops cannot be judged, signed records cannot be checked, records were rejected, or the control run cannot be read, so a page never says "no stop" about a control run it could not read. `-stop-policy` and `-stop-root` check the signatures as an audited deployment does; without them the banner says signatures are not verified. The run list and a run's page say which runs a stop holds (a global stop, a flow stop, a tool stop with a call the journal shows no result for; an agent stop only "may be held", since the agent identity is not journaled), `/stops.json` serves the banner (with `read_at`; a viewer given the policy on a deployment that has not upgraded says its plain stops are ignored by audited processes), and `bide stop -lift` shows how many runs the stop holds before it asks. The control run `@stop` is no longer listed as a run. Guide: docs/guides/kill-switch.md.
