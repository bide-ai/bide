Section: Fixed

Before release, `bide edit` against a Registry or a blocks description let an edit through that added a second problem of a kind the text already had: the config check (`plan.InspectConfig`, `plan.InspectConfigDescribed`) reported only the first type misfit, and the first of each wiring problem (a loop's shape, a node not reached from the entry, a join's routes), so the typed editor, which refuses an edit that adds a type problem or a loop-shape error by comparing the problems before and after, saw nothing new when a second one appeared. The check now reports every one of them: every edge, switch arm, join input and terminal whose types do not fit, up to 100 with a final line saying how many more there are, and every refusal of the wiring checks. `plan.Load` and `plan.Validate` list all the type problems in their error instead of the first. `bide check` and the viewer show the longer lists. `plan.AllTypeProblems` is a new `InspectOption` that lifts the cap of 100 for a caller that compares two reports (the typed editor passes it, so a problem past the cap cannot hide in the count). Where there are several problems the first still leads, so a message or an error that began with it still does; `plan.Load` and `plan.Validate` errors, which name the first problem as before, now go on to name the others after it.
