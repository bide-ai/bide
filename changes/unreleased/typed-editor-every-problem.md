Section: Fixed

Before release, `bide edit` against a Registry or a blocks description let an edit through that added a second problem of a kind the text already had: the config check (`plan.InspectConfig`, `plan.InspectConfigDescribed`) reported only the first type misfit, and the first of each wiring problem (a loop's shape, a node not reached from the entry, a join's routes), so the typed editor, which refuses an edit that adds a type problem or a loop-shape error by comparing the problems before and after, saw nothing new when a second one appeared. The check now reports every one of them: every edge, switch arm, join input and terminal whose types do not fit, up to 100 with a final line saying how many more there are, and every refusal of the wiring checks. `plan.Load` and `plan.Validate` list all the type problems in their error instead of the first. `bide check` and the viewer show the longer lists.
