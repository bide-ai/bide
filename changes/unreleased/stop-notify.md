The kill switch notifies: a stop that is set (`stop_set`, key `stop:<id>`) and a stop that is lifted (`stop_lifted`, key `stop:<id>:lifted`) are notification kinds, observed from the control run so delivery has the notify trail's claim, acknowledgement, retry, overdue and escalation and survives the death of the process that set the stop. `NotifyPending` given `WithNotifyStops(ctl)` reads the control run on each sweep (stops set or lifted within `WithNotifyStopsWithin`, default 7 days), and `NewStopNotifier` with `WithStopObserver` on a `StopSwitch` notifies within the switch's poll interval; both name an event by its key, so any number of processes and both paths send one notification. The observer is handed each change through a single latest-state slot on a goroutine of its own, so a blocked or panicking observer or notifier never delays or fails a check point. A `stop_set` ends with the usual all-clear (reason `lifted`), an audited stop's `stop_lifted` is raised once when the quorum lands, a rejected record raises nothing, and routing and escalation apply. The webhook payload gains `stop` (id, scope, name, reason, setter, host, mode, signed, compensation, lifted_by; no key, signature or secret), the Slack relay escapes the operator text, PagerDuty sends `stop_set` as critical and `stop_lifted` as info, and `bide notify test -kind stop_set` and `stop_lifted` send samples. Guide: docs/guides/kill-switch.md.
