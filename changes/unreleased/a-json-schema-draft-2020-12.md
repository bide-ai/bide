A JSON Schema (Draft 2020-12) for flow configs, at `plan/schema/flow.schema.json` (`$id` `https://raw.githubusercontent.com/bide-ai/bide/main/plan/schema/flow.schema.json`), so editors complete and check a config as it is typed: keys with hover descriptions, the `safety` values, the edge/switch/join forms of a wiring element, the approval block, and a pattern for each form of the `assert` grammar. Point an editor at it with a `# yaml-language-server: $schema=<url>` first line (now on every config in `examples/plan/flows`), a VS Code `yaml.schemas` mapping or a JetBrains JSON Schema mapping (see the "Editor support" section of the plan flows guide). `plan/schema_test.go` keeps it the same as the code: every key `plan.Load` decodes is in the schema and no other, its enums and assertion patterns are the code's own, a table of good and bad configs is accepted and refused alike by the schema and by `Load`, and every sample config is valid under it. The schema checks the file's shape only; names, types and whether an assertion holds are still decided by `Load` and `bide check`.
