The approval intake has a browser page: an approver opens a link from a notification, sees the call, and signs a decision with an Ed25519 key held non-extractable in the browser (WebCrypto, IndexedDB). The page computes the SHA-256 of the canonical arguments itself from what it displays and signs that, signs nothing if the call or its gate changes between the display and the signature, and checks the receipt the endpoint returns. `approvals.PageFiles` and `go run github.com/bide-ai/bide/approvals/cmd/approvepage` give a deterministic bundle with published hashes for an organization to host on an origin of its own; `approvals.WithCORS` lets that origin call the intake (the preflight is answered before authentication); `approvals.WithPage` serves it from the application for development and says so on its face. Both need `WithAuth`. The canonical-arguments encoding and the decision bytes have golden vectors generated by Go (`agent/testdata/canonical_args_vectors.json`) that the page's script is tested against. Passkeys (WebAuthn) are a separate, later design; gates for high-value actions should wait for them.
