Section: Added

`agent.RaisesSafety(reason)` (experimental, with `ToolSpec.RaisesSafety`): `agent.New` now refuses with `ErrConfig` a wrapper whose declared `Safety` is safer than a tool it embeds or unwraps, at any depth (the order is a side effect, then `Idempotent`, then `ReadOnly`), naming the wrapper, the tool and both levels; a wrapper that really does make the call safer declares `RaisesSafety(reason)` (the reason follows the rules of `agent.Trusted`). The reason is in the declarations document (`raises_safety`, and `idempotent` for a retry-safe side effect) and, only when set, in the declarations digest, so existing digests are unchanged. `bide doctor -declarations` lists it and `bide doctor -diff` reports adding it as WEAKENED and removing it as strengthened. `bide doctor -diff` also reports any tool that becomes safer to re-run (side effect to `Idempotent`, or either to `ReadOnly`) as WEAKENED. Behavior change: an agent with such a wrapper (for example a `ReadOnly` wrapper over a side-effecting tool) now fails at `New` until the wrapper declares the inner tool's `Safety` or `RaisesSafety`. See docs/reference/extension-points.md and docs/guides/untrusted-content.md. The declarations format stays `bide.declarations.v1` (experimental), and every document the agent now dumps carries a `tracks_idempotent` member (and, where they apply, `idempotent` and `raises_safety`), so an older `bide doctor` (v0.24.0 and earlier) refuses a new document as having an unknown member. In the other direction, `bide doctor -diff` of a baseline dumped by an older version against a new dump that has an `Idempotent` side-effecting tool reports one WEAKENED line, asking you to regenerate the baseline with the new version, instead of reading the missing member as "not Idempotent": a pipeline regenerates its baseline once after upgrading. Behavior change, broader than `Safety`: the wrapper check on an `Unwrap` chain now also looks inside the tools each chain tool embeds, for every property it checks (approval gate, `Timeout`, `Caps`, `Untrusted` and `Safety`), so an agent whose wrapper reaches a tool by `Unwrap` that in turn embeds a gated, capped, untrusted or less safe tool, and that was accepted before, can now fail at `New` with `ErrConfig` until the wrapper declares the same.
