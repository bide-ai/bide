Section: Fixed

Three paths no longer panic under `GODEBUG=fips140=only`: importing `govern/redislog` (go-redis hashed its script with SHA-1 in package init; the script now uses `NewScriptServerSHA`, so Redis computes the digest and an append still works after `SCRIPT FLUSH`, a restart or a Redis that refuses SCRIPT), verifying an RFC 3161 token that carries a SHA-1 `signingCertificate` attribute (DigiCert's tokens do; the consistency comparison now runs with enforcement off and is still made), and a webhook secret shorter than 14 bytes (under that mode `notify.NewWebhook` returns `agent.ErrConfig` wrapping the new `notify.ErrShortSecret`, a delivery that a secret cannot sign is not sent, `notify.Verify` and `notify.VerifyBody` return it, `notify.Sign` leaves the secret out, `notify.CheckSecret` is the rule, and `relay.New` and the `bide notify` verbs refuse the secret at start; other deployments are unchanged, and 32 bytes or more is recommended). Correction: the documentation said FIPS mode and ML-DSA are mutually exclusive; that holds only for Go's FIPS 140-3 module v1.0.0 (`crypto/mldsa` is unavailable there) and not for v1.26.0 and later, where ML-DSA and hybrid signing work under `GODEBUG=fips140=only`. bide makes no claim of FIPS validation.
