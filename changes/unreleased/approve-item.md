`bide approve -item FILE` (and `bide-hsm approve -item`) takes the run and the call from one call of `bide approve -list -json` output, a file or `-` for standard input (which also needs `-yes`), instead of `-run` and `-call`. The input is the call's object or an array of exactly one, decoded strictly (no repeated name, no invalid UTF-8), and the ids are used exactly as decoded, so an id that ends in a line break or holds a bidirectional or invisible character, which a pasted command line or a shell's `$(...)` cannot carry, can be decided from the command line. `-item` with `-run`, `-call`, `-list` or `-verify-receipt` is a usage error, and the input is limited to 1 MiB. The fallback texts of `bide view` and `bide approve -list` for such ids, the run viewer and approval guides and the CLI references point to it.
