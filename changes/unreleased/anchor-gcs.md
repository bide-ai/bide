Section: Added

New module anchor/gcs: the second production audit.Anchor, which writes every signed tree head as an object in a Google Cloud Storage bucket whose retention policy is locked, with create-only writes, a read-back that refuses a retention, Cloud KMS key, hold or checksum weaker than configured, and a Reader that lists noncurrent generations so a deleted or overwritten newest head does not hide it, errors on two different signed heads of one size and on a well-formed head with a bad signature, and reports what it skipped. New refuses a bucket owned by another project, without a locked retention policy of at least the configured length, versioning, uniform bucket-level access, enforced public access prevention or the configured default key; the package ships least-privilege custom IAM roles (no delete, so no overwrite, and a separate hold-release identity), and builds on the new experimental audit/anchorobj. It was run once against a real bucket and is otherwise tested against an in-memory model; a locked policy cannot be undone, so read the [runbook](docs/testing/gcs-anchor-real-run.md) first, and a run or trail ID in an anchored head cannot be erased, so it must hold no personal data ([guide](docs/guides/anchoring-gcs.md)).
