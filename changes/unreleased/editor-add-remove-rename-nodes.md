bide edit can add, remove and rename a node and write the entry (the first step of the editor's structure phase). Each is a verified splice like the gate and safety forms: the result is checked against the data the operation should produce, computed from the operation alone. A rename rewrites the node's name in the entry, edges, switches, arms, `else`, join inputs and `assert` lines (the last through the assertion grammar, refusing a line it cannot rewrite), and a rename of a gated node reads as weakened because the gate comparison follows names. A removal first lists what else goes (the edges, arms and comments that name the node) and is refused unless the same list is confirmed; `assert` lines naming the node are left in place for the check to report. The editor never changes the entry node without being asked: removing the entry, or the first node of a config with no `entry` key, is refused with a pointer to set_entry. The API gains the operations `add_node`, `remove_node`, `rename_node` and `set_entry`, and `Operation.DryRun`, `Operation.Confirm` and `Applied.Cascade`.
