Section: Fixed

`planview.CheckDiff` and `planview.DiffHandler` (a program's own diff check with its Registries; present since v0.15.0, reproduced on v0.21.0) passed a diff silently when a side had errors against its Registry: such a side has no gates to compare, so a gate removed by changing a block read as no change and `CheckDiff` returned false, where the same diff without Registries reports it. A common cause was one Registry shared by both versions that holds a block the config does not use (an error in `Load`). The diff is now made structurally, as without the Registry, so the weakening is reported as it would be without it; the result is labelled not certified (`DiffView.Fallback`), its verdict is never good, and `CheckDiff` returns true. Every result also says how each side was checked (`DiffView.OldBasis`, `NewBasis`). `bide check -diff` and `bide view -config -diff` pass no Registry, so they were never affected.
