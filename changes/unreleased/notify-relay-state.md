Section: Changed

`bide notify relay` takes `-state <file>` (`relay.Config.StatePath`), which keeps the delivery IDs it forwarded and the event IDs it saw cleared across restarts, written atomically and bounded by `-dedupe`, so a trigger retried after a restart that comes after its clear no longer reopens the PagerDuty incident; a second relay on the same file is refused by an exclusive operating-system lock (released if the holder crashes), and without `-state` the memory still resets on restart, and a state file that cannot be parsed is refused at start. A refusal from Slack or PagerDuty now logs only an allow-listed error token (`relay.StatusError.Code`, replacing `Body`) instead of the first 200 bytes of the reply.
