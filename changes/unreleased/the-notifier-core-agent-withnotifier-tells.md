The notifier core: `agent.WithNotifier(notifier, trail)` tells a `Notifier`, at least once and with a stable `Notification.ID`, when a run halts on an unknown outcome, waits for approval, or is aborted (a saga whose rollback finished), and when recovery keeps failing for a run. It applies to an `Agent` (the event is raised where a drive ends), and to `Recover` and `RecoverLoop` (which also raise `recovery_failing`, counted in time from a `failing_since` record in the trail so a crash loop that restarts the process still alerts). Delivery state lives in a `NotifyTrail`, never in the run's journal: observed, claimed, acknowledged, failing, overdue and cleared records, so two processes cannot both deliver while a claim is live, a restart does not repeat an acknowledged event, a halt resolved or a gate decided before delivery is cleared instead of sent, and an event not acknowledged by its deadline (`WithNotifyDeadline`, default 5 minutes) raises an overdue notice to `WithOverdueNotifier` and keeps retrying. Retries never give up (capped backoff, `WithNotifyRetry`), and `WithNotifyErrors` hears when a delivery is failing. `Agent.FlushNotifications` waits for deliveries in flight. A Notifier reports how a delivery was authenticated with `agent.ReportNotifyAck`. The webhook notifier, the `NotifyPending` sweep and `bide audit` verification follow ([design](docs/design/notifier.md)).

Hardening from an independent review: the overdue notice is derived from the trail and sent inside the round that holds the event's claim (so it survives a restart and a failed first delivery); every `Notify` call is bounded by a quarter of the claim and rounds of different events run concurrently, so one hung sink does not stall the rest, and `RecoverLoop` returns on cancel; another holder's claim counts as live for a skew margin past its `until`, and a new round is paced by the trail, so the claims of an undelivered event stay near four an hour whatever the number of sweeps; a decided gate (single decision, tally, tool or node result) is cleared, not reported; `NotifyPending` also finds aborted runs; any pause closes a recovery failure episode, a run no `Resumer` drives alerts, and a shutdown's cancellation does not; `recovery_failing` carries a class, never the Resumer's error text; an idle notifier holds no goroutine; `FlushNotifications` returns what it could not deliver; a plan flow keeps one notifier per store.
