Section: Added

The `-params` file of `bide identity fetch-crl` and `bide identity check` takes optional members for the values the gate's policy digest covers and a declaration could not state before: `w`, `min_w`, `routine_grace`, `clock_tolerance`, `allow_holds`, `consecutive_numbers`, `retained` and `effective_from` (named as in the policy record), beside the existing `coverage_tolerance`. A file that states all of them builds an approver whose policy digest equals the gate's for the same declaration (`audit.StatusDecl.MissingForDigest` names what a file lacks), so the digest `fetch-crl` prints in its start-up events is comparable, and `bide identity check -expect-digest` is a true equality; with a file that lacks some, `fetch-crl` says which and that the digest cannot be compared, and `check` fails naming them. Existing files parse and behave as before, and unknown members are still refused.
