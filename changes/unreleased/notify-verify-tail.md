Section: Fixed

`bide audit notifications` no longer lets a verdict rest on records nothing attests. An event whose observation, acknowledgement or clearing is only among the records after the newest signed tree head is now `unattested` (a problem) and fails the audit, because anyone who can append to the stored trail could have written it; the report gives the tail's size and time range, and a nonzero `-max-unattested` (library `MaxTailAge`) accepts it, without a signature, when its tail records are that recent; a tail-only `failing_since` or `recovered` record, which has no event key, is judged the same way as an `unattested` recovery-state verdict. New `-routing` (library `Routing`; write it with the new `agent.RoutingOf` from the notifier's own options, whose `NotifyRouting.Receivers` the notifier now routes by) requires each event a delivery to the receivers it routes to, and each due escalation step a delivery to its receiver, else `no_delivery`; without it per-receiver completeness is not checked, which is documented. The verifier also reads the notifier's own fan-out and escalation trails: a delivery to several receivers (`to:<receiver>:<key>`, the default receiver recorded as no name) and an escalation step (which carries its event's operation) no longer fail the operation and receiver checks, and an end-to-end test runs the real engine under every routing shape and verifies the trail, signed and unsigned.
