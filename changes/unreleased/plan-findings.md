Section: Added

`plan.ConfigReport` has a new `Findings` list: for each error in `Problems`, a `plan.Finding` with a `Kind` (`plan.ProblemEdgeTypes`, `ProblemArmTypes`, `ProblemJoinInputTypes`, `ProblemTerminalTypes`, `ProblemSafetyAboveRegistration`, the loop kinds `ProblemLoopNoExitArm`, `ProblemLoopMoreThanOneBackArm`, `ProblemLoopHeadNotAncestor`, `ProblemLoopBodyNotSimple`, `ProblemLoopInnerSwitch`, `ProblemLoopEdgeLeaves`, `ProblemLoopEdgeEnters`, or `ProblemOther`), the full names it is about, `Got` and `Want` where the kind has them, and the message. A tool tells problems apart by kind and names instead of reading messages, which shorten long names and name a wiring element by its position. Findings are complete (not capped at the first hundred type problems), are found beside any other error, and every error has exactly one; `ConfigProblem` is unchanged. A kind's name, names order and `Got` and `Want` formats are stable in 0.x, kinds may be added, and `other` may become a specific kind in any release, so treat it like an unknown kind. See the plan flows guide (Findings). `bide edit` now reads findings instead of internal records. Findings are in the Go API only: `bide check` and the JSON of the viewer and editor pages do not carry them.
