Section: Changed

A CRL whose critical issuing distribution point holds only a full name made of URIs (the shape step-ca stamps on every CRL it signs) is now read instead of refused. Because such a point narrows the CRL's scope (RFC 5280 section 5.2.5), it is evidence of absence only for a certificate whose own CRL distribution points name one of its URIs byte for byte, in a point with no reasons and no cRLIssuer; a certificate that does not name it gets no status from it and the gate waits, as before. A listing in any CRL the issuer signed still revokes, whatever its point. The CRL refresher refuses (an `unsupported-crl` event naming both URLs) a CRL whose point does not name the URL it was fetched from, and `audit.CRL` gains `DistributionPoints`. Every other issuing distribution point (a scope flag, a reasons field, a relative name, a name that is not a URI, a non-critical one) and any delta CRL with one are refused as before.
