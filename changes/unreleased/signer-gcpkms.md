Section: Added

The new module `signer/gcpkms` is an `audit.Signer` whose Ed25519 (`EC_SIGN_ED25519`) or ECDSA P-256 (`EC_SIGN_P256_SHA256`) key lives in Google Cloud KMS, selected by `Config.Scheme` (default P-256, the scheme Cloud KMS offers in an HSM) like the PKCS#11 and AWS KMS signers: it pins a full `CryptoKeyVersion` name (no "latest" alias), refuses a version of the other algorithm or one that is not `ENABLED`, is fail-closed about protection level (only `HSM` and `HSM_SINGLE_TENANT` open by default; `Config.AllowSoftwareKey` and `Config.AllowExternalKey` opt out, and because Google offers Ed25519 in software only the Ed25519 scheme needs `AllowSoftwareKey`, so a bank that needs an HSM key uses P-256), follows Google's data integrity guide (request and response CRC32C checks, a signature checksum mismatch retried up to three times), signs once at `Open`, verifies every signature against the public key (`Config.Timeout` bounds each `Sign`, retries included), and reduces a Cloud KMS client error to its gRPC status code (`gcpkms.CodeError`) so no credential text reaches an error. It is tested through the real Cloud KMS Go client against gcp-kms-emulator v0.10.0 running in the test process (no Docker, no credentials; the separate test-only module `signer/gcpkms/emulatortest`) and a fake client for the failures the emulator cannot produce, never against Google Cloud itself; `examples/hsm-signing` takes `BIDE_GCPKMS_KEY_VERSION` to use it, and the key custody guide gains a Google Cloud KMS section with the custom IAM role.
